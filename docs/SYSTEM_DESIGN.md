# 시스템 설계 — 고색고 ICE-ZERO 자동 제설 모형

기준은 `CONTRACT.md`다. 여기 적힌 핀·상수는 계약 6~8절과 같다. 그림은 같은 폴더의 `img/*.svg`다.

![시스템 구성](img/system.svg)

## 1. 구성

| 부분 | 하는 일 | 실행 위치 |
|---|---|---|
| 모델·엔진 | 수원 ASOS(지점 119)로 다시 학습한 지면온도 예보, 갈래별 예측 동결확률·우선순위 | 맥북 `model/icezero/` |
| 서버·대시보드 | 상태 API, 센서 융합, 자동 출동 판단, 이벤트 기록 | 맥북 `server/gosaek_server.py` |
| 기지 Pico #1 | 갈래 온습도·젖음·조도 측정, 기지 전광판·경광등, 도킹 감지·자동 보충 | `pico/sensors/` |
| 제설차 Pico #2 | 스텝모터 주행, UDP 통신(서보 살포·초음파 정지는 선택, 지금은 달지 않음) | `pico/car/` |
| 사거리 보드 | 검은 종이 도로 + A3 광장, 센서 기둥, 북동쪽 제설기지(출입구 서쪽, N 도로) | 책상 |

- 맥북은 모델을 돌리고 판단한다. 출동은 코드 규칙이 정한다. **LLM(Claude)은 사진을 보는 데만 쓴다**: 패드의 '눈 위치 표시'(표시 전용, 차는 안 움직임)와 사진 판정 API의 두 번째 의견. 서버는 `ANTHROPIC_API_KEY`가 있을 때 Claude를 켜고, '눈 위치 표시'는 그 기기의 브라우저에 넣은 Claude API 키로 서버 없이 Claude API를 직접 부를 수도 있다(계약 0·5절). 화면 문구도 '예측 동결확률', '상대 우선순위'다.
- Pico 두 대는 서로 직접 말하지 않는다. 모두 맥북을 거친다(센서는 USB, 차는 Wi-Fi UDP).
- 모니터는 같은 서버의 `/monitor`를 전체 화면으로 띄운다(계약 5절).

## 2. 데이터 흐름

1. **학습(한 번)**: `data/raw/119/` ASOS 원본 → 피처 → XGBoost 회귀·분류 → `model/models/119/*.json`.
2. **도로**: 모형 갈래는 손으로 정한 `data/roads/cross_arms.json`(임의 도로)이다. Overpass로 받은 고색고 반경 1.5km 도로·교량·건물 분석은 `data/roads/cross_arms_osm.json`에 참고로만 남긴다.
3. **실행(매 순간)**: 서버가 1초마다 엔진 `step()`을 부른다.
   - 엔진은 그 시각의 예보와 갈래 속성으로 `p_freeze`·`level`·`priority`를 낸다.
   - 서버는 기지 Pico의 `@@TEL`을 받아 갈래 `dt`(현장 온도차)와 W 갈래 젖음을 `local`로 넣는다.
   - 출동은 패드의 '전체 청소', 사진 판정 API(`/api/vision/detect`), 기지 조도 신호로만 한다. 차가 idle이고 실행 중인 계획이 없을 때 `plan`을 보낸다. `recommend`는 화면 참고용이다(계약 5절).
4. **표시**: 서버가 `@@SHOW`로 기지 Pico의 링·OLED·LCD에 갈래 상태를 보내고(`beacon`이면 경광등), 대시보드·모니터에 같은 내용을 그린다.
5. **복귀**: 차가 `arm_done`을 보내면 서버가 그 갈래를 3시간 동안 처리됨(`done`)으로 둔다.

## 3. Pico 두 대의 역할

### 기지 Pico #1 (USB 시리얼, 관제실)

- DHT11 4개로 갈래별 온·습도를 재고, 수위 센서로 W 갈래 젖음을, 조도 센서로 W 그늘 밝기를 읽는다.
- 2초마다 `@@TEL` 한 줄을 보낸다.
- 맥이 죽어도 로컬 경고는 계속 돈다: 어느 갈래든 `t ≤ WARN_T`이고 `rh ≥ WARN_RH`이거나, 젖었고 W 갈래 `t ≤ WARN_T`면 3색 LED·부저를 켠다. 3회 연속 거짓이면 끈다.
- 차가 도킹하면(스위치 1초 유지) 사일로 게이트를 800ms 열어 호퍼를 채운다. 한 번 도킹에 한 번만, 20초 쿨다운.
- DHT11은 0~50°C만 잰다. 영하 실외에서는 값이 없거나 0에 붙으므로, 야외 설치 때는 DS18B20 같은 다른 센서가 필요하다(계약 밖 선택 품목).

### 제설차 Pico #2 (Wi-Fi UDP)

- `plan`을 받으면 북동쪽 기지 차고에서 서쪽 182 → 남쪽 230으로 교차로 중심에 간 뒤, 갈래 순서대로 ① 방위 회전 ② `ARM_OUT_MM` 전진(앞 날로 눈을 보드 끝까지 민다) ③ 같은 거리 후진해 중심 복귀를 한다. 끝나면 북쪽 230 → 서쪽을 보고 182 후진해 차고에 들어간다.
- 500ms마다 `tel`로 상태·위치·진행 단계를 보낸다.
- 명령 `stop`·`home`은 항상 우선한다. 차 버튼·초음파 장애물 정지는 달았을 때만 동작한다(지금은 모터만 달았다).
- 전원은 맥 USB, 명령은 Wi-Fi UDP다. Pico 2 W, MicroPython 1.29.

## 5. 전원

| 부하 | 전압 | 전류(대략) | 전원 |
|---|---|---|---|
| Pico #2 자체 | 5V→3.3V | 60~120mA | 맥북 USB |
| 28BYJ-48 두 개 | 5V (ULN2003 VCC=VBUS) | 코일 2상 × 2대 ≈ 400~600mA | 맥북 USB |
| SG90 서보(선택, 달지 않음) | 5V | 100~250mA(이동 순간) | 맥북 USB |
| SR-04(선택, 달지 않음) | 5V | 15mA | 맥북 USB |
| WS2812 링(센서 쪽) | 5V (VBUS) | 밝기 48에서 최대 100mA | 맥북 USB |

- 차는 보조배터리 없이 맥북 USB 하나로 Pico와 모터 두 개를 돌린다. 서보를 달면 스텝모터를 돌릴 때 서보를 동시에 움직이지 않는다(펌웨어가 순서를 지킨다).
- ULN2003 VCC는 **VBUS**, GND는 Pico와 공통으로 묶는다. 모터 전원을 Pico 3V3에서 끌어오지 않는다.
- 기지 Pico #1(선택)도 맥북 USB를 쓴다. 5V 부하는 링·LCD·서보 하나다.
- 정지에서 `STEP_US`(0.6ms)로 바로 밀면 부하가 걸린 모터가 떨기만 했다(2026-11-01). 그래서 구간마다 `START_US`(1.2ms)에서 출발해 가속한다.
- SR-04 ECHO는 5V 출력이다. 1kΩ·2kΩ 분압으로 3.3V에 맞춘다(계약 권장).

## 6. 프로토콜

### 6.1 맥 ↔ 기지 Pico (USB 시리얼, 115200, 한 줄 = 한 메시지)

- Pico → 맥, 2초마다: `@@TEL {"t":{...},"rh":{...},"ok":{...},"wet_raw":40000,"wet":false,"light_raw":21000,"warn":false,"dock":false,"refills":0,"refilling":false,"up":12345}`
- 맥 → Pico: `@@SHOW {"arms":{"N":"risk1","E":"risk3"},"msg":"AUTO ON E>W","beacon":true}` — `msg`는 16자 이내 ASCII(OLED 글꼴이 한글을 그리지 못함). `beacon`이 참이면 링이 경광등처럼 돈다.
- 맥 → Pico: `@@REFILL {"ms":800}` — 수동 보충. 도킹 상태에서만 연다.

### 6.2 맥 ↔ 제설차 (Wi-Fi UDP, 서버 9200 수신, 차 9201 수신)

![프로토콜](img/protocol.svg)

| 방향 | 메시지 |
|---|---|
| 차 → 서버 | `hello {id}`(부팅, `SERVER_IP`가 비면 브로드캐스트) |
| 서버 → 차 | `plan {seq, order}` / `stop` / `home` / `ping` |
| 차 → 서버 | `ack {seq, ok, reason}` |
| 차 → 서버 | `evt {e, seq, arm}` — `plan_start`·`arm_start`·`spray_on`·`spray_off`·`arm_done`·`plan_done`·`stopped`·`obstacle`·`resumed`·`aborted` |
| 차 → 서버 | `tel` 500ms — `state`, `arm`, `phase`, `x`, `y`, `h`, `spray`, `obst_cm`, `up` |

- 같은 `seq`는 한 번만 실행한다(재전송 대비).
- `LINK_TIMEOUT_MS=5000` 넘게 서버 패킷이 없으면 `pause`, 다시 받으면 `resume`.

## 7. 상태기계

![제설차 상태](img/car_states.svg)

- `idle` → `plan` → `run`(depart → turn → out → back … → home) → `plan_done` → `idle`.
- **depart**: 북동쪽 기지 차고 `(764, 250)`에서 서쪽으로 182 전진해 N 도로 가운데로 나오고, 남쪽으로 돌아 230 전진해 중심에 닿는다.
- **turn → out → back**: 갈래 방위로 회전 → `ARM_OUT_MM[arm]` 전진(앞 날로 눈을 보드 끝까지 민다) → 같은 거리 **후진**해 중심 복귀(회전 없음). S도 다른 갈래와 같다.
- **home**: 북향으로 돌아 230 전진해 출입구 높이로 가고, 서쪽을 보고 182 **후진**해 차고에 들어간다. 끝나면 추측 자세를 차고 위치·서향으로 다시 맞춘다.
- 구간마다 `START_US`에서 출발해 가속하고 끝에서 감속한다. 스텝이 `LATE_RAMP_US` 넘게 밀리면 다시 `START_US`부터 가속한다.
- `run` 중 5초 무패킷이면 `pause`, 패킷이 오면 `run`으로 돌아간다.
- `stop` → 모터 코일 OFF, 서보 닫힘. 버튼(선택)을 달면 누를 때 같은 정지, 다시 누르면 남은 구간을 재개한다.
- `home` 명령을 받으면 출입구 길이면 바로 차고로 후진하고, 도로 위면 도로를 따라 중심으로 간 뒤 위 home을 한다(건물을 가로지르지 않는다).
- 초음파(선택, `SONAR_ENABLED=False`)를 달면 8cm 안쪽에서 모터를 세우고, 1초 비면 재개, 10초 넘게 막히면 `aborted`를 보낸다. **후진 중에는 앞쪽 초음파를 무시한다**(차고 벽을 장애물로 보지 않게).

## 8. 안전

- 자동 출동에도 대시보드·패드의 `stop`이 항상 살아 있다. 서버 신호가 5초 끊기면 차가 `pause`한다. 차 버튼·초음파 장애물 정지는 달았을 때만 더해진다(지금은 달지 않음).
- `stop`은 자동 모드를 끈다. 다시 켜야 자동 출동이 재개된다.
- 도킹 스위치는 차가 뒤벽을 미는 힘으로 눌린다. 1초 이상 계속 눌려야 보충하고, 한 번 도킹에 한 번만 연다(쿨다운 20초).
- 차가 없거나 링크가 끊기면 서버는 모의 실행(갈래당 3초)으로 표시만 한다. 실제 살포로 오해하지 않도록 대시보드에 표시한다.
- 결빙을 '확정'했다고 쓰지 않는다. 화면·로그 모두 '예측 동결확률', '상대 우선순위'다.
- 모형의 살포물은 마른 모래·스티로폼 알갱이다. 실제 제설제를 쓰지 않는다(전자부·우드락 손상).

## 9. 보정 방법

### 9.1 기구 상수(차)

1. 바퀴 지름을 캘리퍼로 잰다(지금 값 30mm, 병뚜껑+고무줄). `WHEEL_D_MM`에 넣는다.
2. 두 바퀴 중심 사이 거리를 잰다(지금 값 108mm). `TRACK_MM`에 넣는다.
3. **1m 직진 시험**: 바닥에 1m 줄을 긋고 북향에서 출발시킨다. 실제 이동 거리 `d`를 재서
   `STEPS_PER_REV = 현재값 × 1000 / d` 로 고친다(한 바퀴 스텝은 하프스텝 4096이 기본).
4. **360° 회전 시험**: 바닥에 테이프로 기준선을 긋고 제자리 360° 회전시킨다. 한 바퀴보다 덜 돌면
   `TRACK_MM`을 키우고, 더 돌면 줄인다. 좌우가 어긋나면 오른쪽 모터 스텝 보정값을 조정한다.
5. 두 시험을 번갈아 두 번 하면 1cm 안쪽으로 맞는다.

### 9.2 젖음 센서

1. 마른 채로 `@@TEL`의 `wet_raw`를 읽는다(예: 61000).
2. 물을 묻혀 다시 읽는다(예: 18000).
3. 중간값을 `WET_THRESHOLD`에 넣고, 젖을 때 값이 작아지면 `WET_WHEN_LOW=True`.

### 9.3 현장 온도 보정

- 서버는 시작 30초 평균(또는 `/api/sensors/baseline` 시점)을 갈래 기준값으로 잡는다.
- 이후 `dt = T_k − baseline_k`를 엔진 `local`로 넣는다. 실내 시연에서는 기준값을 다시 잡아야 한다.
- 센서가 10초 넘게 조용하면 서버는 `local`을 비운다(모델만으로 판단).

### 9.4 모델

- 학습·검증 수치와 방법 선택은 `docs/MODEL.md`를 본다.
- 재학습: `python3 -m model.icezero.train --stn 119 --force`.

## 10. 보드 배치

![보드 실측 구조도](img/board_measured.png)

- 흰 우드락 위 검은 종이 도로. 보드 925×910(노란 코트 방향이 가로, 2026-10-31 사진 실측), 도로 폭 135, 가운데 A3 광장 297(동서)×420(남북).
- 중심 `(CENTER_X, CENTER_Y)` = (582, 480). 원점은 판 왼쪽 위, x는 동쪽·y는 남쪽.
- 판 끝까지(중심 기준): N 480 · E 343 · S 430 · W 582. 네 도로 모두 판 끝까지 간다.
- 센서 기둥(DHT11, 중심 기준): N (+105,−220) · E (+220,+105) · S (−105,+260) · W (−220,−105).
- 젖음·조도 센서는 W 갈래(−300,−95) 길가.
