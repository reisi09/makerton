# 2026 수원고교 피지컬 AI 메이커톤: 수원시 민원 데이터 기반 해커톤 아이디어 5선

> Claude(Opus 5.5)와 GPT-6-Astra(max)가 3라운드 토론으로 확정한 최종안. 작성 2026-10-30 KST.
> AI 서비스는 Command Code Provider API로 만든다는 전제다. 공통 스타터 코드는 `starter/`에 있다.
>
> **이 문서는 1차안이다. 수상작 패턴으로 고도화한 최신안은 `최종_산출물_v2.md`에 있다.** 이 문서의 민원 데이터 근거(§2)와 1~3라운드 토론 기록은 그대로 유효하다. 다만 아이디어 목록과 스타터 설명(§3·§6)은 v2가 대체한다. 스타터의 프로필은 v2의 5개로 바뀌었다.

## 0. 결론

**추천 1순위는 ① 보행로·교통약자 접근공간 점유 안내다.** 수원시 민원 키워드에서 '불법 주정차'는 2021~2023년과 2025년에 1위다(2024년은 9위). 그중에서도 인도·장애인 전용구역·어린이 보호구역 관련 키워드가 2019~2025년 내내 나온다. 초음파와 PIR만으로 만들 수 있고, 스타터 코드가 이 아이디어로 바로 돈다.

## 1. 과제 조건
- 행사: 2026.10.30(금)~11.1(일), 매원고 강당(영통구 매탄동). 제작 시간은 약 12시간이다(10/31 9시간 + 11/1 오전 약 3시간). 11/1 오후 전시·평가. 2~3인 1팀이고 초보자도 참가할 수 있다. 1인당 약 10만원 키트를 받는다.

- 사용자 요구: AI 서비스는 Command Code Provider API로 만든다(`https://api.commandcode.ai/provider/v1`). Go 플랜은 API를 쓸 수 없다.

### 2.5 데이터에서 아이디어로
- 수원시 민원은 2021년 이후 '불법 주정차'가 압도한다. 그 안에서도 **보행 공간(인도), 교통약자(장애인 전용구역·어린이 보호구역), 대중교통(버스정류소)** 키워드가 해마다 따로 잡힌다. 그래서 ①과 ③을 나눴다.
- 피코와 기본 센서가 현장에서 재는 것은 '점유 시간', '적재율', '수위 변화', '소리 지속'이다. 위반 여부, 차량 자격, 투기자는 관측할 수 없다. 그래서 다섯 아이디어 모두 **관측값 → 안내·점검 요청**으로 설계했다.

## 3. 아이디어 상세

공통 사항: 판단은 `POST /systemone`(`typesafe/jev`)이 한다. 선택지 확률이 0.80(검증 전 초기값) 미만이면 `review`(노랑, 사람 확인)로 내린다. 네트워크가 안 되면 피코의 로컬 규칙으로 동작하고 파란 LED를 같이 켜서 'AI 아님'을 보인다. 관리자용 초안은 대시보드 버튼으로만 만든다. jev 질문 원문은 `starter/relay/profiles.json`에 있다.

### ① 보행로·교통약자 접근공간 점유 안내 (`access_space`, 23점: 4/5/4/5/5)
- **문제**: 횡단보도 진입부, 인도, 장애인 전용구역이 막혀도 누군가 사진을 찍어 신고하기 전까지 현장에는 아무 안내가 없다.
- **근거**: '인도 불법' df 20,615(2023) → 34,982(2024) → 31,182(2025). '장애인 전용구역' 2021~2025년 매년 12,584~18,651. '어린이 보호구역' 2020~2025년 중 5개 연도. '통학환경 조성' 20,306(2021). 2025년 12월 장애인 주차구역 위반 1,368건. 2026년 6월 장애인전용주차 1,535건.
- **SDG**: 11.2(어린이·장애인 등 취약 이용자의 안전한 교통 접근), 11.7(접근 가능한 공공공간)
- **하드웨어**: HC-SR04(ECHO 분압 필수), PIR(HC-SR501, 대기자), RGB LED, SG90 안내 깃발, 반사판·도로 모형. 부저는 기본으로 끈다. 키트 외 추가비는 약 0~1.5만원[추정].
- **AI 설계**: 상태 `{distance_cm, occupied_s, waiting}` → 선택지 `observe / notice / clear_path / staff_check / review`, 보조 질문 `blocking`(score). 단계는 0 초록, 1 노랑, 2 빨강, 3 빨강+깃발. 초안 버튼을 누르면 '통행공간 점검 요청서'를 만든다(위반 단정 금지).
- **오프라인 규칙**(시연용 단축 시간): 5초 미만 0, 15초 미만 1, 30초 이상이고 대기자가 있으면 3, 그 밖은 2
- **12시간 MVP**: 진입부 1곳, 센서 2개, LED와 깃발, 대시보드. 빼는 것: 카메라, 번호판·차종·자격 판정, 자동 신고, 실제 차단기.
- **시연**: 장난감 차가 잠깐 지나가면 안내가 없다 → 15초 이상 세우면 빨강 → PIR 앞에서 손을 흔들고 30초가 넘으면 깃발이 오르고 관리자 확인 → 대시보드에서 jev 확률을 보여 주고 '요청서 초안' 버튼 → 차를 치우면 초록 → 노트북 인터넷을 끊어 파란 불(로컬 규칙)을 보여 준다.
- **리스크**: 초음파는 사람과 차를 구별하지 못하므로 이름을 '점유 안내기'로 한다. 반사판이 없으면 센서 오류(파랑)가 난다.

### ② 공동 배출장소 넘침·방치 알림 (`drop_zone`, 22점: 3/5/4/5/5)
- **문제**: 공동 배출장소가 넘치거나 바깥에 물건이 오래 남아도 수거 담당자가 늦게 안다. 무단투기 CCTV를 403대(2021) → 499대(2023)로 늘렸지만 식별에 한계가 있다는 보도가 있다.
- **근거**: 청소자원과·자원순환과 접수 4,138(2015) / 4,185(2020) / 3,379(2023). '쓰레기 투기' df 2,520(2025, 25위). 2025년 12월 쓰레기 무단투기+충전구역 합산 1,638건(쓰레기만의 수치가 아님).
- **SDG**: 11.6(도시 폐기물 관리). 발생량 감축은 재지 않으므로 12.5는 핵심 목표로 내세우지 않는다.
- **하드웨어**: HC-SR04 두 개(수거함 내부 적재, 바깥 지정 구역), PIR, RGB LED, SG90 '수거 점검' 깃발, 상자. 키트 외 약 0.9~1.5만원[추정].
- **AI 설계**: `{fill_ratio, outside_occupied_s, motion_recent, window_open}` → `observe / guide / collection_needed / clear_drop_zone / review`. 배출 허용 시간대는 관리자가 입력한다. 초안 버튼은 수거 담당자용 '수거·정리 요청서'를 만든다.
- **MVP**: 상자 1개, 바깥 구역 1곳, 수거 완료 버튼. 빼는 것: 투기자 경고·추적, 음성, 자동 뚜껑, 재질 인식.
- **시연**: 종이공으로 통을 채우면 빨강+깃발. 바깥에 상자를 두고 떠나면 '정리 요청', 손이 잠깐 지나가면 무시. '수거 담당' 학생이 비우면 초록.
- **리스크**: 종이 한 장이 센서를 가리는 오탐은 중앙값과 지속시간으로 줄인다. 사람을 경고 대상으로 삼지 않는다.

### ③ 버스정류소 진입공간·승차 도움 표시 (`bus_stop`, 21점: 4/4/4/4/5)
- **문제**: 정류소 정차면이 막히면 버스가 차로에 서서 승하차한다. 휠체어·고령 승객은 도움을 청할 방법이 없다.
- **근거**: '버스 정류장' df 13,373(2020) / 8,280(2023) / 1,286(2024), '버스정류소 불법' 5,604(2023) → 6,019(2024) → 4,518(2025). 대중교통과 접수 4,495(2015) → 6,259(2023).
- **SDG**: 11.2(대중교통 접근성)
- **하드웨어**: HC-SR04(정차면), 버튼 2개(승차 도움 요청, 버스 도착 모사), RGB LED, SG90 안내판
- **AI 설계**: `{bay_occupied_s, bus_arriving, help_requested, help_wait_s}` → `wait / check_space / staff_help / both / review`. 도움 버튼 접수등은 AI를 기다리지 않고 바로 켠다.
- **MVP·시연**: 도착 모사 버튼 + 정차면에 차를 두면 '공간 확인' 안내. 도움 버튼을 누르면 '기사·관리자 안내'. 둘이 겹치면 우선 안내. 실제 버스 연동은 하지 않고, 모사 버튼임을 화면에 밝힌다.
- **리스크**: 정상 정차한 버스와 다른 차를 구별하지 못한다. 그래서 '도착 예정 + 점유'라는 맥락으로만 판단한다.

### ④ 빗물받이 배수 지연 경보 (`drain`, 20점: 2/4/4/5/5)
- **문제**: 비가 오는데 빗물받이 위쪽 물이 빠지지 않는 상태를 일찍 알려 덮개·낙엽 막힘을 점검하게 한다.
- **근거(약함, 그대로 밝힘)**: 다년 민원 키워드가 없다. 4개 구 건설과·안전건설과 접수 5,556(2015) → 12,079(2019) → 7,620(2023)은 간접 근거다. 2026년 5월 기준 빗물받이 70,579개는 시설 수다. 수원시가 2026년 '빗물받이 상태별현황'(막힘·쓰레기·잡초 사진)을 공개한 것은 행정 관심의 근거다.
- **SDG**: 11.5(수해 피해 감소), 13.1(기후 적응력)
- **하드웨어**: 수위 센서 두 개(ADC), 빗물 센서, RGB LED, SG90 우회 표지, 2칸 투명 수조·호스. 키트 외 약 0.9~1.8만원[추정].
- **AI 설계**: `{up_level, down_level, up_change_20s, rain, normal_drain_s, since_inflow_s}` → `normal / inspect_inlet / inspect_backflow / review`. 상류 0.9 이상은 AI와 별개로 즉시 고수위 경고를 낸다(`REFLEX=True` 권장).
- **시연**: 컵으로 같은 양을 붓고 정상 배수와 종이 필터로 일부 막은 경우를 비교한다. 하류 수위를 올리면 '역류 점검'이 뜬다. 물은 전자부와 떨어진 수조에만 넣는다.
- **리스크**: 노출 전극은 부식된다. 쓰고 나면 말린다. 원인을 확정하지 않고 '점검 필요'라고만 말한다.

### ⑤ 공사장 지속 소음 작업 알림 (`work_noise`, 18점: 3/4/4/3/4)
- **문제**: 작업자는 소음이 얼마나 오래 이어졌는지 모른다. 주민 민원이 나기 전에 작업자가 스스로 조정하게 한다.
- **근거**: '소음 진동' df 3,357(2019), '공사 소음' 12,063(2020), '공사 중단' 8,469(2023)·4,848(2024), '수직구 공사' 8,183(2023). 2023년 팔달구 소음 민원 1,099건 중 공사 소음이 542건(49.3%)이다(새수원신문 2024-05-24). 4개 구 환경위생과 접수 2015~2023년 연 4,898~13,236건(간접).
- **SDG**: 3.4(건강·웰빙), 11.6(도시 환경 부담), 둘 다 간접
- **하드웨어**: 아날로그 사운드 센서, 진동 센서(SW-420), RGB LED, SG90 표지. 부저는 쓰지 않는다.
- **AI 설계**: `{rel_rms, loud_s, impulses_30s, vibration, work_hours}` → `observe / transient / check_work_noise / review`. 값은 기준 대비 배수이고 dB(A)가 아니다.
- **시연**: 나무 블록을 한 번 두드리는 경우(보류)와 약하게 계속 두드리는 경우(점검 안내)를 비교한다. 작업자 역할 학생이 멈추면 해제된다.
- **리스크**: 강당 소음 간섭이 가장 큰 위험이다. 마이크를 가까이 두고, 시작할 때 기준을 보정하고, 남는 오탐은 그대로 기록한다. 그래서 시연 점수를 3점으로 낮췄다.

## 4. 추천과 선택 가이드
- **초보 2~3인 팀**: ①. 센서 2개와 스타터 코드 그대로 출발할 수 있고 근거가 가장 강하다.
- **환경·SDG 다양성을 원하는 팀**: ②(폐기물) 또는 ④(기후). ④는 근거가 약하다는 점을 발표에서 먼저 밝힌다.
- **역할 분담**: 1명은 센서·배선·모형, 1명은 중계 서버·jev 프로필·대시보드를 맡는다. 3인이면 1명이 데이터 근거 발표와 반복 시연 기록을 맡는다.
- **심사에서 보여 줄 것**: 민원 데이터(§2) → 센서 원시값 → jev 확률(대시보드) → 실물 동작 → 회복 → 인터넷 차단 시 로컬 규칙(파랑). 이 순서다. 같은 상황을 단순 임계값 규칙과 비교한 기록이 있으면 'AI가 왜 필요한가'에 답할 수 있다.

## 5. GPT-6-Astra(max)와의 토론 요약

진행: 1라운드는 서로 보지 않고 각자 데이터를 조사해 5개씩 제안했다. 2라운드는 상호 비판과 근거 검증, 3라운드는 합의다. GPT 측은 `omp -p --model openai-codex/gpt-6-astra --thinking max`로 실행했다. 원문은 `debate/claude_round1.md`, `astra/round1.md`, `debate/claude_round2_critique.md`, `astra/round2.md`, `astra/round3.md`에 있다.

| | Claude 1라운드 | GPT 1라운드 |
|---|---|---|
| 핵심 데이터 | 권익위 민원 빅데이터 2019~2026 연도별 건수·키워드, 공공데이터 4종 | 수원 기본통계 '민원서류 처리' 2019~2024, 2025년 12월 기사, 팔달구 소음, 포트홀 실적 |
| 5개 안 | 전용구역 지킴이, 소각장 악취 환기창, 스쿨존 경보등, 클린존 배출함, 버스정류소 | 통학로 점유 알림, 배출장소 넘침, 빗물받이 배수, 공사장 소음, 요철 카트 |
| 통신 | Wi-Fi HTTP | USB 직렬 |
| AI | jev 판단 + chat 자동 신고문 | jev 판단만 |

**서로 잡아낸 오류**
- GPT가 Claude 쪽에서 찾은 것: 청소 부서 집계에 '교육청소년과'가 섞임, 2026년 6월 보고서 수치 오독 3건(교통 3,922→3,022, 광고물 1,365→1,305, 비중 56.4%→57.8%), CCTV 403대의 시점 누락(2021년 값), '키워드 1위'에 연도 누락. Claude가 원본을 다시 렌더링·재집계해 모두 맞음을 확인하고 고쳤다.
- Claude가 GPT 쪽에서 찾은 것: 5년 근거가 증명서 발급 통계(93.75%)뿐이라 아이디어와 연결되지 않음. 2~5번 근거가 한 달·한 구·시설 수에 그침. 생성형 서비스 층이 없음. GPT는 이를 받아들여 권익위 장기 자료를 근거의 중심으로 옮겼다.
- 둘 다 독립적으로 찾은 것: 공공데이터 15093355의 2024년 = 2023년 복제.

**쟁점과 결론**
1. 센서로 위반·자격을 판정할 것인가 → **하지 않는다.** RFID 권한 카드, '불법 정차' 질문, 자동 신고문을 뺐다. Claude가 양보했다.
2. 지역 이슈인 소각장 악취 환기창 → **제외한다.** '소각장 폐쇄·영통 소각장' 키워드는 이전 요구이지 악취 사건이 아니다. MQ-135는 48시간 넘는 예열이 필요하고 교차 감도가 있다. Claude가 양보했다.
3. 통신 → **USB 기본, Wi-Fi 선택.** 핫스팟 단말 간 차단, 노트북 방화벽 같은 실패 지점을 줄인다. 첫날 점검을 통과한 팀만 Wi-Fi를 쓴다. Claude가 양보했다. 스타터에는 두 경로가 모두 있다.
4. 생성형 AI → **대시보드 버튼으로 사람이 요청할 때만** 초안을 만든다. 비용 상한과 사람 확인을 함께 지킨다. 절충했다.
5. 요철 카트 → **제외한다**(기구 제작 위험, 약한 근거). GPT가 양보했다. 버스정류소를 '승차 도움'으로 바꿔 독립 안으로 남겼다.

### 5.1 3라운드 결과
- **GPT-6-Astra는 최종 5개, 순위, 점수(23 / 22 / 21 / 20 / 18)에 모두 동의했다.** 초보 팀 추천도 ①로 Claude와 같다. 이유는 다년 근거가 있고, 관측 대상이 점유·지속시간으로 좁고, 통과·장기 점유·제거를 한 모형에서 보여 주기 쉽다는 것이다.
- GPT는 스타터 코드에서 시연을 망칠 결함 5개를 실행으로 찾아냈다. Claude가 모두 고치고 다시 검증했다(§6.1).
  1. 변경 감지 키가 `occupied_s`에 묶여 다른 프로필에서 KeyError가 남 → 로컬 단계와 참/거짓 값으로 만드는 범용 `state_key()`로 바꿈
  2. USB 응답을 기다리는 동안 센서·동작이 최대 8초 멈춤 → USB를 비차단 수신으로 바꾸고, 응답은 요청할 때의 상황 키와 지금 키가 같을 때만 적용
  3. 줄바꿈 없는 조각이나 깨진 JSON에서 대기하거나 종료됨 → 글자 단위 버퍼로 완성된 줄만 해석하고 깨진 프레임은 버림
  4. 센서 오류 동안에도 점유 시간이 쌓임 → 오류가 나면 점유 타이머 초기화
  5. `/report`와 대시보드에 인증이 없어 타인이 유료 생성을 누를 수 있음 → 팀 토큰 필수(`?token=`, 폼 hidden 필드)

## 6. Command Code 공통 스타터(`starter/`)
```
[피코 WH + 센서] ──USB 직렬(기본) 또는 Wi-Fi HTTP──> [relay/server.py] ──HTTPS──> Command Code
   pico/main.py      @@REQ/@@RES 줄, seq 확인         /decide → /systemone (jev)        typesafe/jev
   pico/config.py    serial_bridge.py(USB 모드)       대시보드 / , 초안 /report → chat   deepseek-v4.1-flash
```
- `relay/server.py`: Python 표준 라이브러리만 쓴다. 팀 토큰 검사(피코 요청, 대시보드 `?token=`, 초안 버튼), 확률 0.80 미만이면 review, seq 반환, 이벤트 기록(`events.jsonl`), 대시보드, 수동 초안. 시작할 때 프로필의 선택지와 단계가 맞는지 검사한다.
- `relay/profiles.json`: 아이디어 5개의 jev 질문과 단계표
- `relay/serial_bridge.py`: USB 모드용(pyserial 필요)
- `pico/main.py`: ① 예시 구현(초음파+PIR → LED·깃발). USB 비차단 수신, 요청 당시 상황과 같을 때만 AI 응답 적용(seq + 상황 키), 비차단 Wi-Fi 재연결, 센서 오류 처리(파랑만, 점유 타이머 초기화), 오프라인 표시(파랑 동시 점등)를 담았다.
- 실행 방법과 첫날 5분 연결 점검은 `starter/README.md`에 있다.

| 누적 시간 | 할 일 | 끝났다는 증거 |
|---|---|---|
| 0~1h | 부품 확인, ECHO 분압, 센서 값 출력 | 손을 대면 거리·PIR 값이 바뀜 |
| 1~2h | USB 브리지로 중계 서버 연결(Wi-Fi는 5분만 시도) | 대시보드에 이벤트가 찍힘 |
| 2~4h | API 키 설정, jev 실제 호출, 프로필 문구 조정 | 실제 확률이 대시보드에 뜸 |
| 4~6h | LED·깃발 동작, 오프라인·센서 오류 표시 | 인터넷을 끊으면 파랑+로컬 규칙 |
| 6~8h | 모형 제작, 시연 시간 단축값 조정 | 시나리오 1회 완주 |
| 8~10h | 정상·이상·교란 조건을 각각 5회 반복하고 결과 기록 | 혼동 기록표 |
| 10~12h(11/1 오전) | 배선 고정, 발표 자료(§2 데이터 + 대시보드 캡처), 리허설 | 시작부터 복구까지 연속 시연 |

## 8. 주의사항
- **전기**: RP2040 GPIO는 3.3V 전용이다. HC-SR04 ECHO는 반드시 분압한다. 서보는 VBUS나 별도 5V로 공급하고 GND를 공통으로 묶는다. 220V 릴레이, 실제 차단기, 펌프는 쓰지 않는다.
- **키·비용**: API 키는 노트북 환경변수에만 둔다. 피코, 코드, 스크린샷에 넣지 않는다. jev는 입력 100만 토큰당 $0.042라서 1,000회(회당 800토큰)여도 약 $0.034다[추정]. 초안은 버튼을 누를 때만 만든다. `typesafe/jev`는 ZDR 헤더(`x-cmd-zdr: 1`)를 지원하지 않으므로 개인정보를 보내지 않는다.
- **데이터 표현**: df를 신고 건수라고 하지 않는다. 2024년 부서 통계는 쓰지 않는다. MQ·마이크 값을 ppm·dB로 표시하지 않는다.
- **현장 표현**: '위반 단속기'가 아니라 '안내·점검 요청 장치'라고 부른다. 모형 결과를 도시 전체 효과로 키워 말하지 않는다.
