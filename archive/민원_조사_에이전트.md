# 민원 현장 조사 에이전트 (9라운드, 2026-10-31 KST)

> 사용자 요청: "좀 더 어려운 task, LLM 쓸 만한 걸로."
> 앞선 '등굣길 위험 조사관'은 규칙만으로 충분해서 LLM이 필요 없다는 데 양측이 동의했다. 이 문서는 그 대안이다.
> 원문: `astra/round9_agent.md`(GPT 판정: 수정 채택)

## 0. 결론
- **과제는 사람이 승인하는 민원 조사 보조 에이전트다.** 주민이 자유 문장으로 민원을 설명하면 LLM이 다음을 한다.
  - 주장과 조건을 나눈다.
  - 필요한 확인 질문을 한다.
  - 피코의 센서를 도구로 써서 측정 계획을 짜고, 결과와 정정에 따라 계획을 다시 짠다.
- **수치 비교와 관측 판정은 코드가 한다.** 판정은 '해당 조건에서 관측됨 / 미관측 / 측정 불가' 셋으로 나눈다. 측정 계획과 최종 기록은 사람이 승인한다.
- **LLM이 필요한 이유**: 민원 설명에는 미리 짜 두지 않은 복합 조건이 섞인다. 예: "차가 멈출 때만 시끄럽고 통로도 막혀요". 조사 도중에 정정도 들어온다. 예: "그 소리 말고 비 오는 밤에 벽이 떨리는 거요". jev 분류 + 유형별 측정 템플릿으로는 이런 변화에 맞춰 조사를 다시 설계할 수 없다.
  - 이 주장은 같은 입력을 템플릿 기준선에도 넣어 비교해서 보인다. **차이가 없으면 LLM 채택 근거를 철회한다.**

## 1. 실호출로 확인한 것 (2026-10-31, Command Code)
| 시험 | 결과 |
|---|---|
| 도구 호출(`deepseek-v4.1-flash`, `reasoning_effort=low`) 2건 | 2건 모두 `finish_reason=tool_calls`, 3.4~4.1초 |
| 소음 민원 "밤 10시쯤 공사장 쿵쿵, 바닥이 울려요" | 소리와 진동 측정을 함께 호출했다. 가짜 피코 값으로 끝까지 돌리면 10.6초, 도구 2회였다. "30분 넘게"는 측정 불가, "밤 10시·공사장 가동"은 미관측으로 분리했다 |
| 배수 민원 "빗물받이에 물이 안 빠져요" | 확인 질문 → 수위 측정 → 초음파 스캔 2회 순서였고 16.0초, 도구 4회였다 |

**시험에서 드러난 문제와 대응**
- LLM이 초음파로 '막힘 요인'을 확인하려 했다. 센서로 알 수 없는 일이다.
  - 대응: 도구 설명에 센서의 한계를 적는다. 관측 판정은 코드가 하고, LLM은 그 판정을 바꿀 수 없다.
- 최종 JSON 앞뒤에 설명문과 코드 블록이 붙었다.
  - 대응: 서버가 JSON만 뽑아 쓰고, 형식이 틀리면 승인 대기로 올리지 않는다.
- 담당 부서 후보가 일반 명칭으로 나왔다.
  - 대응: 부서 라우팅은 12시간 범위에서 뺀다. 2015~2025 부서 접수표는 과거 분포일 뿐 현행 담당 부서의 근거가 아니다.
- 위 시험은 가짜 피코 값으로 했다. 실물 센서, 정정 시나리오, 템플릿 비교는 아직이다.

## 2. 파이프라인
```
민원 문장(검수·비식별)
  → LLM: 주장·조건 분해, 확인 질문, 측정 계획(도구 호출 목록)
  → 사람 승인(대시보드)
  → 피코 도구 실행: 서보로 돌린 초음파 거리, 상대 소리 크기
  → 코드: 배경·전후 비교 → 관측됨 / 미관측 / 측정 불가
  → LLM: 정정·엇갈린 결과를 반영해 재계획하거나 종료
  → 현장 기록·답변 초안 → 사람 승인
```
- 실시간 반응이 아니라 조사 도구다. 루프 한 번에 10~16초 걸린 것은 이 용도에서 문제가 되지 않는다.
- 안전 경계는 코드가 지킨다. 도구 인자 범위, 서보 동작 범위, 호출 상한, 중단 조건을 코드로 제한한다. 측정 계획은 실행 전에 사람이 승인한다.

## 3. 12시간 최소 범위 (GPT 수정 반영)
- **도구 3개**: `scan_distance(angle, samples)`(서보 + 초음파), `measure_sound(duration)`(상대값, dB 아님), `ask_complainant(question)`
- **코드가 맡는 것**: 배경 비교, 관측 판정, 로그, 인자·호출 상한, 중단 조건
- **12시간에서 뺄 것**: 진동·조도·수위·시야선 도구, 과거 기록 검색, 부서 자동 라우팅, 다중 노드
- 도구 수를 늘리기보다 **정정에 따라 조사가 바뀌는 흐름**을 완성한다.
- **모형**: 두드림 소리를 낼 수 있는 '공사' 모형, 정차 공간과 장난감 차, 서보 위에 초음파·마이크 헤드
- **역할**
  - 하드웨어: 모형과 센서 헤드
  - 펌웨어: 피코 도구 호출 규약(USB JSON 요청·응답)
  - LLM·서버: 에이전트 루프, 승인 화면, 비교 코드, 템플릿 기준선
- **스타터 재사용**: USB 브리지, 대시보드 승인, `call_api`/`chat_text`(`reasoning_effort`), `cmd_id` 중복 방지. 도구 호출 규약은 새로 만든다.

## 4. 시연 핵심 장면 (GPT 제안)
- **장면 A, 복합 조건**: "차가 멈출 때만 시끄럽고 통로도 막힌다"
  - 차가 서기 전과 후의 소리·거리를 비교한다.
  - 결과가 엇갈리면 두 주장을 나누고, 질문과 측정 계획을 바꾼다.
- **장면 B, 실행 중 정정**: 측정을 마친 뒤 "그 소리 말고, 비 오는 밤에 벽이 떨리는 것"이라고 정정한다.
  - 앞서 잰 소음값을 이 민원의 증거에서 뺀다.
  - 시간대와 장비의 한계를 밝히고 추가 확인으로 돌린다.
- 조건과 정정은 시연 중에 즉석으로 바꾼다. 같은 입력을 jev + 템플릿 기준선에도 넣어 세 가지를 비교한다: 정정 반영 여부, 필요한 질문을 했는지, 불필요한 호출 수.

## 5. 근거 (정직한 표현, GPT 문안)
"제시된 2019~2025 수원 자료는 장기간의 민원 규모와 분야 다양성을 보여준다. 이를 배경으로 다양한 민원 설명을 다루는 조사 보조를 제안한다."
- 권익위 수원 민원 건수는 2019년 223,897건, 2021년 871,233건, 2025년 374,777건이다(E1).
- 5년 이상 반복 근거는 주정차, 장애인 전용구역, 어린이·통학 축에만 해당한다(E2, `다른_주제_후보.md`). 소음·배수가 5년 넘게 이어졌다거나, 이 에이전트가 필요하다는 것이 검증됐다는 뜻은 아니다.

## 6. 위험
- **센서값을 과장할 위험**: 거리와 상대 소리만으로 통행 방해, 소음 원인, 위반을 확정하지 않는다. 미관측을 민원을 부정하는 근거로 쓰지 않는다.
- **느린 오호출이 연쇄될 위험**: 계획 승인, 호출 상한, 중단 조건으로 막는다.
- **개인정보**: 민원 문장은 `x-cmd-zdr: 1`을 붙인 chat에만 보낸다. 실호출에서 이 헤더로 HTTP 200을 확인했다. jev로는 보내지 않는다.
- **LLM 필수성**: 템플릿 비교 결과가 나오기 전까지는 미입증이다.
