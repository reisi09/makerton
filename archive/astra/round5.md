# 5라운드: 고도화안 합의

**설계와 최종 순위에 합의한다. 다만 현재 AGENT 구현을 시연 준비 완료로 판정하지는 않는다.**

## A~D에 대한 입장
- **A — 조건부 동의.** MVP는 Pico 1대·여러 센서로 고정하고, 여분 Pico의 실제 지급을 확인한 뒤 두 번째 보드를 선택 확장으로 허용한다. 고유 `DEVICE_ID`·보드별 USB 중계 또는 검증된 Wi-Fi가 필요하며, 아래 결함 수정 전에는 다중 노드 기능의 존재를 동작 보장으로 제시하지 않는다.
- **B — 동의.** `read_context` 도구 호출 제안을 철회하고 작은 맥락을 프롬프트에 직접 넣는다. `seq/rev/관측 시각`과 허용 목록 검사는 유지하고, chat 출력은 `action_id`·`target_id` 각 하나만 받는다.
- **C — 동의.** 노트북의 로컬 TTS를 선택 기능으로 두되 사람이 승인한 동일 제안만 읽는다. 상황이 바뀐 대기 음성은 취소하고 중복 재생을 막으며, 음성 실패 시 화면 안내를 유지한다.
- **D — 동의.** 순위와 6항목 점수를 재검토했으며 기존 점수를 유지한다. 완료 검증은 GPT 4라운드 점수에 이미 반영됐고, 도구 호출 제거·선택 노드·TTS만으로 실기 미검증이나 강당 소음 간섭이 해소되지는 않는다.

확정 범위: 1번은 휠체어 이용자의 A/B 모형 통로·화살표, 4번은 배수 재실험 점검대, 5번은 주민 ‘지금 시끄러워요’ 버튼을 더한 조치 효과 재측정이다. 지팡이·버스 쪽 패널·차수판은 선택 확장이며, 시각장애인 단독 보행 안전이나 실제 침수 방어를 보장하지 않는다.
공통 원칙: jev 상태 LED는 자동, chat의 단일 행동·TTS는 사람 승인 후 실행한다. 완료는 센서와 사람의 확인으로 판정하며, 경고 단계 상승과 A/B 경로 선택·완료 상태는 별도 필드로 관리한다.

## AGENT 구현의 주요 결함 5개
대상: `starter/relay/server.py` 361줄 검토본, SHA256 앞 16자리 `f7697af5c73a5261`. 검토 중 추가된 `/approve` 경로·대시보드 승인 버튼은 확인했고, 미구현이라고 지적하지 않는다.

1. **38, 87–94, 136–142, 228–229줄 — 승인 대상 미지정·승인 우회:** 피코는 제안 ID 없이 전역 최신 제안을 승인한다. A 버튼이 B의 새 제안을 승인하는 경우를 재현했고, `AGENT_APPROVAL=0`은 승인 없이 실행한다. **수정:** MVP는 ID·내용을 보여 주는 대시보드 승인만 사용하고 자동 적용 분기를 제거한다. 피코 승인을 유지하려면 사용자가 본 제안 ID·대상·버전을 명시적으로 묶는다.
2. **95–103, 117, 135, 228–236줄 — 낡은 상황으로 승인:** `action` 이름만 비교하며, 승인 요청의 새 센서값은 검사 전에 반영되지 않고 poll에서는 아예 버린다. `occupied=true`를 보내도 저장된 `false`로 승인·명령 전달됐다. **수정:** 의사결정 상태의 `rev`·최근 수신 시각·참조 노드를 저장하고, 최신 관측 확인과 승인·큐 등록을 같은 잠금 안에서 처리한다. 전달 시에도 버전·유효성을 재검사한다.
3. **81–82, 128–130줄 — 명령 계약 미강제:** 복수 노드 명령이 그대로 허용되고, 아직 유효한 `pending_cmd=3`을 새 `1`이 덮어쓴다. Pico도 새 `cmd`를 대입한 뒤 기본 단계와만 `max`하므로 기존 명령 유지시간 중 하향을 막지 못한다(`pico/main.py:219–220,239–249`). **수정:** 단일 행동·대상 스키마를 강제하고, 경고 명령은 서버·수신부 모두 기존 유효 명령과 최댓값을 취한다. 정상 복구는 별도 완료 확인·만료 규칙으로 처리한다.
4. **230–236, 260–268줄 — 수신 확인 전 명령 삭제:** `pop`이 응답 송신보다 먼저여서 응답을 적용하지 못해도 명령이 사라진다. 첫 poll 응답을 미적용한 뒤 재조회하면 `cmd`가 없었다. **수정:** `command_id`·만료시각을 붙여 ACK까지 보관하고, Pico는 같은 ID를 중복 실행하지 않으며 적용 확인 뒤 ACK한다.
5. **112–114, 257–263줄 — 제안 생성 누락:** `len(nodes)>1` 때문에 합의한 1-Pico MVP에서는 AGENT 제안이 생성되지 않는다. 최소 간격 안의 변경도 버린 뒤 `action`이 유지되면 재시도하지 않았다. **수정:** 1노드에서도 수동 제안을 허용하고, 자동 모드를 쓸 경우 간격 중 변경은 최신 1건으로 보류했다가 간격 종료 후 처리한다. 호출 상한은 유지한다.

검증: 실제 `Handler`를 루프백 HTTP 서버로 실행하고 upstream만 메모리 응답으로 대체해 위 승인·상태·큐·poll·호출 누락 경로를 재현했다. 서버는 종료했으며 `starter/`는 수정하지 않았다. Command Code API·피코 실물·TTS는 실행하지 않았다.

**합의: A~D와 최종 5개 안에 동의하며, AGENT 실물 시연은 위 결함 수정·재검증을 조건으로 한다.**
