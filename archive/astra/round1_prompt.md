# 하드웨어 전제
- Raspberry Pi Pico WH: RP2040(듀얼 Cortex-M0+ 133MHz, SRAM 264KB, 플래시 2MB), CYW43439 Wi-Fi(2.4GHz)/BLE, 헤더 납땜 완료. MicroPython 또는 Arduino C++로 개발한다.
- '기본 센서'는 흔한 입문 키트 수준으로 본다. 예: DHT11/22, HC-SR04 초음파, PIR, 조도(CdS), 사운드(마이크 모듈), MQ 계열 가스, 토양수분, 수위, 빗물, 진동/기울기, 적외선, MPU6050, 버튼/가변저항, 서보, 부저, LED/RGB, SSD1306 OLED, 릴레이. 카메라 비전이나 고가 모듈(PM2.5 레이저 센서, mmWave 등)을 쓰면 '선택 추가'로 표시하고 가격을 함께 적는다.
- '피지컬 AI'는 감지 → 판단(AI) → 물리적 작동/알림으로 이어지는 고리를 뜻한다. 판단 단계의 AI 서비스는 아래 Command Code API로 만든다.

# AI 서비스 조건(사용자 요구): Command Code Provider API
- 팀은 AI 서비스를 Command Code Provider API로 개발하려 한다. 모든 아이디어의 AI 판단·생성 단계는 이 API를 쓰도록 설계한다. RP2040 온디바이스 규칙/필터는 전처리나 오프라인 대비용으로만 둔다.
- 공식 문서: https://commandcode.ai/docs/provider . Base URL은 `https://api.commandcode.ai/provider/v1`, 인증 헤더는 `Authorization: Bearer <CMD_API_KEY>`다.
  - `POST /chat/completions`: OpenAI Chat Completions 형식. 예: `deepseek/deepseek-v4.1-flash`(입력 $0.15/M, 출력 $0.6/M 토큰), 무료 모델 `poolside/laguna-s-2.1-free`, `reflection/beam:free`.
  - `POST /responses`: OpenAI Responses 형식. `POST /messages`: Anthropic Messages 형식(Claude 모델 전용).
  - `POST /systemone`: 결정 모델 `typesafe/jev`. 텍스트 state와 typed questions(`noul` 예/아니오 확률, `choice` 선택지 확률, `score` 루브릭 점수)를 받아 확률 JSON만 돌려준다. 텍스트를 생성하지 않는다. 입력 $0.042/M 토큰이고 한 요청에 질문 100개까지 넣을 수 있다. 응답이 작아서 센서 상태 → 확률 → 액추에이터 임계값으로 잇기 좋다.
  - 이미지 입력을 받는 모델도 있지만 피코에는 카메라가 없다.
- 설계할 때 따질 제약은 다음과 같다.
  - 피코 W는 2.4GHz만 지원하고 캡티브 포털에 붙지 못한다. 행사장에서는 휴대폰 핫스팟을 전제로 한다.
  - MicroPython `urequests`로 HTTPS를 호출할 수는 있다. 다만 TLS 메모리, 인증서 검증, API 키를 기기에 저장하는 문제가 있다. 피코가 직접 호출할지, 노트북 중계 서버(키 보관)를 거칠지 정하고 이유를 적는다.
  - 호출 지연(수백 ms~수 초) 동안 동작을 정하고, 네트워크가 끊겼을 때의 대체 동작을 정한다.
  - 시연 하루 동안의 예상 호출 수와 비용을 적는다.

1. 수원시 민원 데이터를 직접 조사한다. 최근 5년 이상을 다루고, 연도별 수치가 있는 자료를 우선한다. 후보 출처는 다음과 같다.

   - 국민권익위원회 민원 빅데이터, 국민신문고 지역별 민원 동향
   - 수원시 통계연보의 민원 처리 현황
   - 행정안전부 안전신문고 지역별 통계
   - 수원시 보도자료, 수원시정연구원 보고서, 언론 보도
   파일 데이터를 내려받을 수 있으면 실제로 열어 수치를 확인한다. 내려받은 파일은 `/Users/choiwuseck/Documents/omp/suwon-makeathon-2026/astra/data/`에 저장한다.
2. 민원 상위 유형과 연도별 추이를 정리한다. 그중 피코 WH와 기본 센서로 '현장에서 감지·판단·작동'할 수 있는 문제를 고른다.
3. 아이디어 5개를 제안한다. 각 아이디어에 다음을 넣는다.
   - 해결할 문제와 민원 근거(수치, 연도, 출처 URL)
   - SDG 목표와 세부목표 번호
   - 시스템 구성: 센서, 액추에이터, 통신·대시보드
   - Command Code API 설계: 엔드포인트와 모델, 피코가 보내는 입력(센서 상태 요약), 출력 스키마(예: jev 질문 정의 또는 JSON 응답 형식), 출력값이 액추에이터를 움직이는 규칙, 오프라인 대체 동작, 시연 하루 호출 수와 비용
   - 12시간 안에 만들 MVP 범위와 뺄 기능
   - 심사 시연 시나리오(강당 부스에서 재현할 수 있어야 함)
   - 주요 기술 리스크와 대응
   - 예상 부품 목록과 키트 외 추가 비용
4. 5개 아이디어에 '민원 근거 강도 / 구현 가능성 / 피지컬 AI 완성도 / 시연 임팩트 / SDG 적합성'을 각각 1~5점으로 매기고 순위를 정한다.
5. 이 과제에서 흔히 빠지는 함정(근거 없는 수치, 피코로 불가능한 AI, 시연 불가 등)을 3~5개 적는다.
