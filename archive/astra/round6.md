# 6라운드: 비초보 팀 기준 최종 판정

모델: `openai-codex/gpt-6-astra`, `thinking=max`.
기존 세션의 두 실행은 시간 제한으로 최종 파일을 만들지 못했다. 확인된 맥락과 Claude의 수정 제안만 넘긴 새 세션에서 아래 최종 판정을 받았다. 새 조사·새 점수·실행 검증은 수행하지 않았다. 아래는 해당 응답 원문이다.

1. **최종 판정: 조건부 채택.** 숙련팀 대상 추천안으로는 채택하되, 한 이동 건의 경로안내·승차인계를 연결하는 실내 시연으로 범위를 제한한다.
2. **선행 조건:** Pico 2대 확보와 Command Code API 키 복구. 보드 확보는 미확인이고 현재 키는 만료 상태이므로, 둘을 충족했다고 전제하지 않는다.
3. **위험 1 — 신규 구현·통합 부담:** 스타터에 이동상태기계·경로실행이 없고, 작업 배정이 12시간을 모두 채워 지연을 흡수할 여유가 없다.
4. **범위 수정:** 경로·정차 지점은 사전 지정하고 이동 한 건만 시연한다. 자유 경로 탐색·TinyML·세 번째 노드·버스 API는 제외한다.
5. **위험 2 [INFERENCE] — 상태 불일치와 잘못된 완료:** 지연·중복 보고나 재차단 때문에 공유 상태가 실제 상황보다 앞서갈 수 있다.
6. **범위 수정:** 호스트 한 곳만 상태 전이를 확정한다. 재차단·센서오류·보고 끊김은 보류하고, 재계획은 사람 승인 후 사전 지정 경로 선택으로 제한한다.
7. ‘정차면 확보’는 센서 단독 판정이 아니라 담당자 현장 확인으로 처리한다. 시연 완료에는 통과 감지와 당사자 확인이 모두 필요하다.
8. 로컬 규칙은 즉시 표시, jev는 분류, chat은 허용 행동 1개 제안만 담당한다. 경로 변경·음성은 사람 승인 없이는 실행하지 않는다.
9. **안전 경계:** 센서가 못 보는 길의 상태·통행 가능성·실제 보행 안전은 보장하지 않는다. 사람을 서보로 밀어 공간을 확보하지 않는다.
10. **정정 적용 원칙:** “초보팀 아니야”만 반영한다. C++·TinyML·기구 제작 숙련도나 Pico 2~3대 지급까지 확대 해석하지 않는다.
