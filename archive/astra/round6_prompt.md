# 6라운드: 숙련팀 기준 재평가

사용자 정정: **"초보팀 아니야."** 지금까지는 포스터의 '초보자 가능' 문구를 근거로 초보 2~3인 팀을 가정했다. 그래서 '구현 가능성(12h)'을 보수적으로 매겼고 추천도 그 기준으로 했다. 이제 다음을 전제로 다시 평가한다.
- MicroPython/C++, 납땜, 간단한 기구 제작(골판지·3D 프린트), Python 웹, ML 기초를 다룰 수 있는 2~3인 숙련팀
- 키트가 1인당 지급되면 피코 WH가 2~3개 있다[추정, 미확인]
- 제작 시간 12시간, 하드웨어 범위(Pico WH + 기본 센서 + 저가 선택 부품), Command Code API 사용, 수원 민원 근거, 사람 승인·완료 검증 원칙은 그대로다.

Claude는 숙련팀이라면 다음 고도화를 MVP로 올릴 수 있다고 본다(동의·반대를 밝혀라).
1. 두 단계 AI: 피코에서 TinyML(Edge Impulse의 RP2040 배포, Arduino/C++)로 소리·진동 패턴을 분류하고, 노트북 Command Code LLM이 상황 해석·계획을 맡는다. 예: 소음 실험대가 '공사형 충격음 / 박수·말소리'를 기기에서 분류해 배경 혼동 문제를 줄인다.
2. 무선 다중 노드(Wi-Fi HTTP, 필요하면 BLE) + 에이전트 허브(스타터에 구현·가짜 upstream 검증 완료: 승인, rev 검사, cmd_id)
3. 공공데이터 실시간 연동: 경기도 버스도착정보 API(3번), 기상청 단기예보 API(4번), 수원 단속 시간대 분포(2022-23, 794,738건)를 위험 사전확률로 사용(1번). API 키는 오늘 밤 미리 발급한다.
4. Shepherd처럼 '몸으로 느끼는 유도'(진동 패턴·서보 측면 밀기)
5. 평가 지표: 조건별 반복 시행 혼동표, 지연시간 측정, 단순 임계값 대비 비교

# 할 일 (`astra/round6.md`, 한국어, 60줄 이내)
1. 위 1~5 각각 동의·반대와 이유(1~2줄)
2. 숙련팀 기준으로 최종 5개를 다시 채점(같은 6항목, 1~5)하고 순위를 매긴다. 순위가 바뀌면 이유를 적는다. 흔한 아이디어(스마트 쓰레기통 등)는 수상 경쟁력에서 감점한다.
3. 숙련팀 '플래그십' 하나를 정한다. 두 아이디어를 합치는 안(예: 1번 경로 안내 + 3번 승차 인계를 '교통약자 한 사람의 이동 전 과정'으로 묶기)도 검토한다. 플래그십에 대해 다음을 적는다.
   - 노드 구성
   - 12시간 일정
   - 3인 역할 분담
   - 시연 90초 대본의 핵심 장면 3개
   - 가장 큰 기술 리스크 2개와 대응
4. 오늘 밤 미리 준비할 것(키, 계정, 부품, 데이터)을 목록으로 적는다.

# 규칙
- `astra/` 밖 파일은 읽기만 한다. Command Code API는 호출하지 않는다. 확인하지 못한 사실은 [추정]으로 표시한다.
- 끝으로 플래그십 이름과 새 순위만 짧게 출력한다.
