# 할 일
1. **실제 수상작 조사(최소 10건)**. 대형 해커톤과 학생 대회 가운데 '하드웨어·센서 + AI + 사회문제' 수상작을 찾는다.
   - 후보 출처: Devpost에 기록된 대형 해커톤 우승작(TreeHacks, HackMIT, PennApps, Cal Hacks, Hack the North, MHacks 등), Google Solution Challenge(SDG 기반 학생 대회), Microsoft Imagine Cup, NASA Space Apps, Hackster.io 대회, Samsung Solve for Tomorrow, 삼성 투모로우 솔루션, 국내 청소년 메이커톤·해커톤
   - 각 수상작마다 다음을 적는다: 대회·연도·상, 링크, 무엇을 만들었는지(센서·AI·사용자), 왜 이겼는지(심사 포인트). 확인하지 못한 수상 사실은 [추정]으로 표시한다.
2. **수상 패턴 추출**: 수상작들에 반복해서 나타나는 설계 패턴 6~8개를 정리한다. 예: 구체적 사용자 이야기, 닫힌 고리(행동 변화), 여러 노드·지도, LLM 에이전트·도구 호출, 예측, 시민 참여, 시연의 놀라운 순간.
3. **현재 5개 진단**: 무엇 때문에 단순해 보이는지 아이디어별로 2줄 이내로 적는다.
4. **고도화 아이디어 5개 제안**. 기존 안을 고쳐도 되고 새로 만들어도 된다. 제약은 그대로 지킨다.
   - Pico WH + 기본 센서(저가 선택 부품 허용, 가격 표시)
   - Command Code API: jev 판단 + chat LLM. 피코에서 LLM을 돌리지 않는다.
   - 초보 2~3인이 약 12시간 안에 만든다.
   - 수원시 민원 근거: `data/evidence_summary.md`의 수치를 인용한다. 새 수치를 쓰면 출처 URL을 단다.
   - 각 아이디어에 다음을 적는다.
     - 참고한 수상작과 가져온 패턴
     - 사용자 이야기(누가, 언제, 무엇이 달라지는가)
     - 시스템(노드 수, 센서, 액추에이터, 데이터 흐름)
     - LLM 역할(판단·설명·도구 호출·요약 등 구체적으로)
     - 12시간 MVP와 확장 기능
     - 시연에서 심사위원을 놀라게 할 장면
     - 심사 포인트, 리스크, 키트 외 비용
5. 채점: '민원 근거 / 구현 가능성(12h) / 피지컬 AI 완성도 / 시연 임팩트 / SDG 적합성 / 수상 경쟁력(참신성)' 6개 항목을 각 1~5점으로 매기고 순위를 정한다.
