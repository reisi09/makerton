# 8라운드: LLM이 대안을 만들고, 사람이 실물로 확인하는 새 주제
**1순위: 사생활·채광 합의창.** 단속·경로 안내가 아니라, 서로 다른 생활 요구를 실물 모형에서 협의한다.

## 2. 공통 제작·LLM 원칙
- 비초보 2~3인, Pico WH **1대 완결형**으로 설계한다. 세부 숙련도·기본 센서 종류는 미확인이다. 노트북·USB 전원·추가 저가 부품 확보가 전제[추정]; Pico 2대는 확보될 때만 확장한다. 실제 시설 대신 종이·골판지 모형을 쓴다.
- 노트북에서 가상 인물의 문장을 타이핑 → Command Code API chat(`deepseek/deepseek-v4.1-flash` 등)에 모형 기능·센서 상태와 함께 전달 → 대안/실험/장면 제안 → 사람 승인 → 허용 명령만 USB로 Pico에 전달한다. 음성·카메라·행정 시스템 연동은 12h 범위에서 제외한다.
- 실시간 각도·동작시간 제한과 정지 버튼은 Pico 로컬 규칙이 맡는다. 승인 전 구동 금지, API 실패 시 새 동작 없음. 완료는 센서 관측과 당사자 확인으로만 정한다. 위반·자격·책임·현실 시설의 안전은 판정하지 않는다.
- `typesafe/jev` 확률 분류는 이번 핵심에 필요 없어 제외한다. ZDR 미지원 조건을 포함해 실제 개인정보·민원 원문은 어느 모델에도 보내지 않는다. 현재 키 만료로 chat 실호출·지연·아래 동작은 미검증이며, 90초는 시연 목표다.
- **“규칙이면 되잖아” 검증:** 고정 메뉴 입력이라면 맞는 지적이다. 아래는 미리 등록하지 않은 가상 요구·정정·반례에 따라 대안/실험/장면을 다시 만드는 과제다. 같은 입력을 고정 템플릿과 비교해야 하며, 자유문장→JSON 변환만 보여주면 LLM 필수성 입증 실패다.
- 점수는 **설계 평가[추정]**, 각 1~5점. 순서는 **민원 근거 / 12시간 구현 / 피지컬 AI / 시연 / SDG / 수상 경쟁력**이다. 성능 측정이나 실제 심사 결과가 아니다.

## 후보 1. 사생활·채광 합의창
- 이야기[추정]: 저층 주민은 “밖에서 집 안은 안 보였으면 좋겠지만 낮에도 어두운 건 싫다”고 한다. 전부 가리기와 그대로 두기 사이의 대안을 직접 보고 고르고 싶다.
- 근거·SDG: A의 5개년 접수(2019년 19,388, 2023년 20,523)와 2025년 `프라이버시 보호` df 2,241. **SDG 11 주거환경, 16 참여적 의사결정**에 연결하는 설계다.
- 피지컬: **1대**에 종이 루버·서보 1개·내부/외부 조도센서 2개·승인/정지 버튼, 별도 저전압 서보 전원과 공통 접지. 모형 집 안에는 식별용 그림을 놓는다. **2대**면 다른 관찰 위치의 센서·확인 버튼을 분리한다.
- LLM 필요: “전체를 막자는 건 아니고, 앉아 있을 때만…” 같은 정정을 앞선 요구·실측과 대조해 확인 질문, 양보 조건, 대안 두 개를 새로 만든다. 센서로 반박된 대안은 수정한다. 고정 각도 메뉴는 이 협의 내용을 대신하지 못하며, 규칙은 각도의 허용 범위만 검증한다.
- 하지 않는 일: 사생활 침해·일조권·방범 성능 판정, 새 부품이 있는 척한 제안, 승인 없는 구동. 조도는 모형의 상대 밝기일 뿐이다. **밝기는 센서, 그림이 보이는지는 사람이 확인**하고 주민 역할 참가자가 수용해야 모형 협의 완료다.
- 12h: 4h 모형·루버·센서, 3h 로컬 제어·호스트, 3h 대화·승인 UI, 2h 반례·통신 실패 시연. 창 1개와 제한된 각도 범위만 구현하며 실제 창문은 제어하지 않는다.
- 90초 핵심: 0~15초 요구 입력 → 15~35초 두 대안과 양보점 검토 → 35~55초 승인·루버 구동·조도 확인 → 55~75초 “내 눈높이에서는 아직 보여요”라는 새 반례로 재제안 → 75~90초 재승인·실물 확인. 양립 불가하면 합의 미완료를 표시한다.
- 가장 큰 위험: 단순 자동 블라인드로 보일 수 있다. 조도 임계치 제어가 아니라 **현장 반례로 협의안이 바뀌는 과정**을 보여야 한다. 모형에서의 합의가 실제 주거 분쟁 해결을 입증하지는 않는다.
- 점수: **3 / 4 / 5 / 5 / 4 / 4 = 25/30**.

## 후보 2. 손으로 바꾸는 공원 설계회의
- 이야기[추정]: 공원 독서 모임을 여는 주민은 꽃을 보며 혼자 앉고 싶은 사람과 서로 마주 보고 이야기하고 싶은 사람의 요구를 함께 반영하고 싶다.
- 근거·SDG: B의 5개년 접수(2019년 45, 2023년 32), 2020년 `공원 설계` df 18,016. **SDG 11 공공공간, 16 참여적 의사결정**. 소수 부서 접수와 큰 키워드 df는 서로 다른 지표라 비교·합산하지 않는다.
- 피지컬: **1대**에 3슬롯 모형판·종류별 저항값을 단 벤치/화단 블록·슬롯별 ADC 입력·제안 위치 LED. 사람이 옮긴 블록의 종류·위치를 다시 읽는다. **2대**면 별도 비교판을 두어 서로 다른 배치안을 동시에 확인한다.
- LLM 필요: 원문 요구 사이에서 함께 만족할 부분과 양보가 필요한 부분을 찾아 배치안·설명을 만들고, “화단은 그대로 두고 혼자 앉는 자리도 남겨”라는 새 조건으로 재협의한다. 고정 투표 메뉴와 달리 선택지 자체를 구성한다. 슬롯 중복·수량은 규칙이 검사한다.
- 하지 않는 일: 다수 의견을 정답으로 선언하거나 공원 설계·시설 안전을 승인하지 않는다. 제안은 3슬롯에서 가능한 배치로 제한한다. **블록 감지와 참가자들의 수용 확인**이 모두 있어야 해당 배치 협의 완료이며, 이견은 그대로 남긴다.
- 12h: 4h 블록·저항 식별 보정, 3h 상태판·LED, 3h 대안 생성·이견 반영, 2h 배치 변경 시연. 벤치·화단 두 종류만 다루며 도시 전체 설계나 이동 경로 안내는 제외한다.
- 90초 핵심: 0~20초 상반된 요구 입력 → 20~45초 대안 승인·LED 표시·블록 이동 → 45~65초 센서로 배치 확인 → 65~90초 새 조건에 따른 수정안과 남은 이견을 실물 두 배치로 비교한다.
- 가장 큰 위험: 투표판에 챗봇을 붙인 것처럼 보일 수 있고, 모형 이동은 사람이 한다. **블록을 실제로 바꾼 뒤 그 상태를 반영한 새 제안**이 없으면 피지컬 AI 강점이 약하다.
- 점수: **3 / 4 / 3 / 4 / 5 / 4 = 23/30**.

## 후보 3. 말로 재현하는 창호 고장
- 이야기[추정]: 주민은 “천천히 닫으면 괜찮은데 손을 놓으면 다시 벌어진다”고 설명했지만, 방문 때 증상이 안 보여 같은 설명을 반복한다. 수리 전 재현 조건부터 남기고 싶다.
- 근거·SDG: C의 5개년 접수(2019년 1,358, 2023년 1,714), 2025년 `시공 상태` df 761. 창호 고장의 장기 발생량은 아니다. **SDG 11 주거환경, 12 수리·사용기간 연장**에 연결하되 실제 수명 연장 효과는 미검증이다.
- 피지컬: **1대**에 느슨한 걸쇠를 가진 종이 창·저토크 서보·닫힘/걸쇠 접점 2개·정지 버튼. 접점의 시간순 변화를 기록한다. **2대**면 창과 손잡이 측 측정기를 분리한다. 움직임은 보호된 모형 안에서만 실행한다.
- LLM 필요: 제보의 시간순 서술·정정에서 경쟁 가설을 만들고, 허용된 느리게/빠르게 닫기·손 놓기 실험 중 구별에 필요한 절차를 제안한다. “닫힘 접점은 켜졌지만 걸쇠는 안 걸렸다”는 관측으로 가설과 다음 질문을 바꾼다. 단순 고장 코드 분류와 다르다.
- 하지 않는 일: 고장 원인 확정·하자 책임·수리 지시·실제 창호 구동. **접점 기록과 제보자의 ‘같은 증상’ 확인**을 묶은 재현 기록까지만 완료로 삼고, 재현되지 않으면 미재현이라고 남긴다.
- 12h: 4h 창·걸쇠·접점 모형, 3h 시간순 기록·동작 제한, 3h 가설/실험 대화, 2h 반례 시연. 모형 1개·허용 동작 3종만 구현하며 실제 설비 진단은 제외한다.
- 90초 핵심: 0~20초 모호한 설명 → 20~40초 질문·실험 승인 → 40~60초 첫 실험이 가설을 반박 → 60~80초 수정 실험 승인·재현 → 80~90초 제보자가 센서 기록과 증상이 일치함을 확인한다.
- 가장 큰 위험: 3동작만 외운 시연은 규칙 트리로 충분하다. **미등록 표현·제보 정정에 따른 질문과 가설 수정**이 나아지는지 비교해야 하며, 좁은 모형에서 LLM 필수성을 입증하기는 1번보다 어렵다.
- 점수: **2 / 4 / 4 / 4 / 4 / 3 = 21/30**.

## 후보 4. 읽고 만지는 이야기 상자
- 이야기[추정]: 도서관에 온 어린이가 “왜 주인공이 물건을 돌려줬는지 모르겠다”고 한다. 설명을 반복하는 대신 인형과 물건을 옮기며 자기 말로 이야기를 다시 만들고 싶다.
- 근거·SDG: D의 5개년 접수(2019년 79, 2023년 34)만 있는 **약한 간접 근거**다. 독서 지원 민원으로 해석하지 않는다. **SDG 4 학습 지원, 10 참여 기회**에 연결하는 설계다.
- 피지컬: **1대**에 물건 놓기 감지 스위치 2개·LED·서보 인형 1개·정지 버튼. 실제 물건의 이동을 다음 장면 입력으로 쓴다. **2대**면 두 참여자의 상자를 분리해 공동 이야기를 만든다.
- LLM 필요: 참가자의 설명·새 결말 요구와 실제 물건 위치를 함께 받아 인과관계가 이어지는 짧은 이야기와 다음 행동을 새로 쓴다. “악당 없이 서로 도와서 끝내자” 같은 현장 조건을 반영하는 창작·재설명은 고정 분기 낭독과 다르다.
- 하지 않는 일: 독해력·장애·학습 효과 판정, 아동 개인정보 수집, 승인 없는 발화·구동. 진행자가 문장과 동작을 승인한다. **센서가 확인한 장면 수행과 참가자의 종료 확인**만 완료로 표시한다.
- 12h: 4h 상자·스위치·인형, 3h 센서-장면 연결, 3h 새 이야기 생성·승인 UI, 2h 물건 위치와 서사 불일치 시연. 팀이 쓴 짧은 가상 이야기·물건 2개만 쓰고 실제 도서 원문·음성 입력은 제외한다.
- 90초 핵심: 0~20초 이야기에 대한 질문 → 20~40초 새 장면 승인·인형 동작 → 40~60초 참가자가 예상과 다르게 물건을 옮김 → 60~80초 새 결말 조건까지 반영한 이야기 승인 → 80~90초 마지막 장면 수행·종료 확인.
- 가장 큰 위험: LLM 창작 역할은 분명하지만 **민원 문제와의 연결이 가장 약하다**. 재미있는 교구라는 사실만으로 수원 민원 해법이라고 주장할 수 없다.
- 점수: **1 / 4 / 4 / 5 / 4 / 3 = 21/30**.

## 3. 1순위와 현재 추천안 비교
- **사생활·채광 합의창 추천:** 장기 공동주택 행정 수요에 주거 관련 키워드를 보강할 수 있고, 자유로운 요구 → 대안 협의 → 물리 변화 → 반례 반영을 한 모형에서 보여준다. 점수뿐 아니라 이번 핵심인 LLM 역할과 실물 변화의 연결을 우선했다.
- **경로 안내 + 승차 인계보다 나은 점[추정]:** LLM이 이미 정해진 판단에 문장만 붙이지 않고 대안·양보 조건을 만든다. 1대에서 눈에 보이는 구동과 센서 피드백이 가능하며, 실제 이동·탑승을 유도하지 않아 그 안전 책임을 피한다.
- **못한 점:** 주정차·접근공간 키워드에 비해 세부 문제의 장기 직접 근거가 약하다. 상대 조도와 모형 시야로 실제 채광·사생활을 검증할 수 없고, 협의의 효용·갈등 감소도 입증되지 않았다. 생성형 대화 지연과 무근거 제안이 시연 위험이다.
- **착수 조건:** 유효 API 키로 새 가상 요구와 센서 반례를 넣은 2차 제안을 실호출하고, 승인 전 무동작·로컬 정지·확인 전 미완료를 모형에서 검증한다. 고정 템플릿과 차이가 없으면 LLM 필수성 주장을 철회한다. 현재는 자료 대조를 마친 설계 제안이지 제작·실증 결과가 아니다.
