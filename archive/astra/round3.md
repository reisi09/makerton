# GPT 측 3라운드: 최종 합의

## 1. 합의
Claude 최종안의 **5개 후보·순위·점수(23 / 22 / 21 / 20 / 18)에 모두 동의한다.** 반대 항목과 수정 점수는 없다.
다만 점수는 설계 평가다. df를 신고·위반 건수로 바꾸지 않고, 상위 100위 미수록을 0건으로 해석하지 않으며, 불안정한 2026년 키워드 값은 제외한다. 아이디어 합의가 스타터의 실행 준비 완료를 뜻하지는 않는다.

## 2. 남은 시연 결함 5개
경로는 프로젝트 루트 기준이다. 검토 중 추가된 오프라인 표시까지 읽었으며, `pico/main.py` 검증 스냅샷의 SHA-256 접두사는 `9fc94c985be1a`다.

1. `starter/pico/main.py:177` - 변경 감지 키가 `occupied_s`·`waiting`에 고정돼 있다. 다른 프로필에 맞게 센서·로컬 함수를 바꿔도 `drop_zone` 입력에서 **KeyError 'occupied_s'**로 루프가 종료됐다. - 프로필별 변경 감지 키도 정의하고, 각 프로필의 실제 입력으로 메인 루프까지 연결한다. JSON 프로필 검사만으로는 잡히지 않는다.
2. `starter/pico/main.py:112,129-139,179-185` - USB·HTTP 요청을 같은 루프에서 기다려 센서 갱신과 작동이 멈춘다. USB 무응답에서 **8초 뒤에야 경고가 작동**했고 `REFLEX`도 호출 뒤 적용된다. `seq`가 같아도 기다리는 동안 현장 상태는 바뀔 수 있다. - 수신 대기를 샘플링·안전 경고와 분리하고, 응답을 최신 관측과 대조한 뒤 적용한다.
3. `starter/pico/main.py:132-138` - 개행 없는 부분 프레임은 `readline()` 안에서 대기해 바깥 8초 제한을 무력화한다. 깨진 `@@RES` JSON은 처리되지 않은 예외로 종료된다. - 비차단 수신 버퍼로 마감 안에 완성된 줄만 파싱하고, 불완전·잘못된 프레임은 폐기해 로컬 동작을 유지한다.
4. `starter/pico/main.py:75-76,83` - 센서 오류에서 `occupied_since`를 지우지 않아 미관측 시간도 점유로 누적한다. 점유 시작→오류→60초 시점 복구 입력에서 **점유 60초·관리자 확인 단계**가 나왔다. - 오류 때 연속 점유 타이머를 초기화하고 유효 관측이 이어질 때만 다시 누적한다.
5. `starter/relay/server.py:108-114,141-155` - `/report`가 토큰 검사 전에 분기한다. 인증 없는 요청도 `write_report` 예약과 **303 응답**까지 진행돼, Wi-Fi 공개 시 타인이 유료 생성을 요청할 수 있다. - 대시보드와 `/report`에 팀 인증을 적용하고 폼 요청에는 CSRF 검사를 둔다. Pico용 `/decide` 인증만으로는 보호되지 않는다.

검증: 원본 함수에 가상 센서·시간을 넣어 실행하고, 부분 USB 줄은 호스트 파이프로 재현했다. 개행이 없으면 8.15초 뒤에도 대기 중이었다. `/report`는 스레드 실행을 차단한 채 예약 여부만 관찰했다.
실제 Pico·센서·핫스팟은 미검증이며 **Command Code API 호출은 0회**다. 스타터와 `astra/` 밖 파일은 수정하지 않았다.
