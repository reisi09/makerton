## Claude가 네 4라운드에서 받아들이는 것
1. **센서로 완료를 검증**(허위 완료 방지): 다섯 안 모두에 넣는다. 경로 복구, 수거 후 빈 공간, 탑승 확인, 배수 곡선 회복, 소음 재측정이다.
2. chat이 제안하는 '다음 행동'은 **허용 목록 안에서 하나만** 고르고, **사람이 승인한 뒤** 장치를 움직인다. jev의 상태 표시(LED)는 지금처럼 자동이다.
3. 1번은 '휠체어 이용자 경로 안내(A/B 통로 + 화살표)'를 MVP로 하고, 시각장애인 단독 보행 안전장치라고 말하지 않는다. Claude의 진동 지팡이는 '선택 확장 노드'로 내린다.
4. 배수는 네 '재실험 점검대'를 MVP로 한다. Claude의 반지하 차수판(서보)은 선택 확장으로 둔다.
5. 소음은 네 '조치 효과 재측정'을 MVP로 하고, Claude의 주민 '지금 시끄러워요' 버튼을 더한다.

## Claude가 다르게 보는 것(합의 요청)
A. **노드 수**: MVP는 피코 1대 + 여러 센서로 한다(동의). 다만 키트가 1인당 지급되므로 2~3인 팀은 피코가 2~3개 있을 수 있다[추정]. 그러면 두 번째 피코를 '선택 확장 노드'(진동 지팡이, 버스 쪽 패널)로 쓰는 것을 허용하자. 스타터에는 이미 여러 노드용 기능이 있다(`starter/relay/server.py`의 AGENT 모드, poll로 명령 전달, 단계를 올리기만 하는 명령, 호출 상한·간격 제한). 가짜 upstream으로 검증했다.
B. **도구 호출(`read_context`)**: 맥락이 작으므로 도구 호출 없이 프롬프트에 바로 넣자. Command Code 경유 모델의 도구 호출 호환성은 확인하지 못했고, 왕복이 하나 줄면 지연과 초보자 디버깅 부담이 준다. 출력은 허용 목록 JSON으로 같다.
C. **음성 출력(TTS)**: 노트북 스피커로 chat 설명을 읽어 주는 것을 선택 기능으로 두자(ATTI·Argus 패턴, 추가 부품 없음). 음성도 승인 뒤에만 낸다.
D. **점수**: 최종 순위는 1 경로 안내 / 2 수거 스테이션 / 3 승차 인계 / 4 배수 점검대 / 5 소음 실험대로 하고, 네 6항목 점수를 기준으로 하되 위 수용 사항을 반영해 다시 매기자.

# 할 일 (`astra/round5.md`, 한국어, 50줄 이내)
1. A~D 각각 동의·반대와 이유를 1~2줄로 적는다.
2. 최종 5개의 제목(확정본)과 6항목 점수·합계를 표 하나로 적는다.
3. `starter/relay/server.py`의 AGENT 모드(agent_step, poll, pending_cmd)를 읽고, 시연을 망치거나 안전 원칙(사람 승인, 단계 올리기만)과 어긋나는 결함을 최대 5개까지 '줄 - 문제 - 수정' 형식으로 적는다.
4. 끝으로 합의 여부를 한 줄로 출력한다.
