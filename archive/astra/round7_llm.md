# 7라운드: LLM 역할 판정

모델: `openai-codex/gpt-6-astra`, `thinking=max`. 도구·조사 없이 Claude가 압축한 맥락과 제안만 보고 답한 원문이다(2026-10-30 KST).

사용자 질문: "llm은?"
Claude 진단: 경로 선택·상태 전이·완료는 규칙이 맡는 것이 맞으므로 LLM 비중이 약하다. 그래서 "규칙으로 되잖아"라는 질문에 취약하다.
Claude 제안: LLM을 언어 계층으로 둔다. 역할은 (a) 자유 문장 → 스키마 JSON, (b) 대상별 안내, (c) 민원 유형 분류(jev)와 신고 초안(chat)이다.

1. **수정 채택.** 안전 판단은 규칙이 맞다. LLM 비중을 늘리기보다 자유문장 처리에서 템플릿보다 나은 효용을 보여야 한다.
2. **1순위: 요구·제보 구조화.** chat이 구조화 후보를 만들고, jev를 쓴다면 상태 판정 대신 요청 의도 분류에 둔다. 둘을 반드시 연쇄 호출할 필요는 없다.
3. “A 사용불가”를 확정하지 말고 **출처·원문·대상 노드·시간·요구 조건**을 추출한다. 승인과 규칙 검증을 거쳐 반영하며, 사전 경로 밖 통로를 만들지 않는다.
4. **2순위: 기존 `/report` 초안 유지.** 300자·위반판단 금지 계약을 지킨다. 대상별 안내는 우선 템플릿으로 처리하고, ‘불법’ 민원 유형 판정은 기각한다.
5. **빠진 위험 ①:** 유효한 JSON도 부정·조건·시간을 오독하거나 지시 주입을 담을 수 있다. 스키마 검증과 별도로 원문 대조·허용 필드 검증이 필요하다.
6. **빠진 위험 ②:** 번호판을 빼도 장애 관련 요구·위치·이동 시각이 외부 API에 전달된다. 출력뿐 아니라 전송 전 입력도 최소화하고 저장 범위를 정해야 한다.
7. **평가 보완:** 30문장은 스모크용으로 보고, 프롬프트 작성에 쓰지 않은 표현·부정·상충 제보·미등록 노드를 포함한다. 같은 입력·출력 계약으로 템플릿/키워드 기준선과 비교한다.
8. 추출 정확도 외에 **핵심 조건 누락·반전, 근거 없는 필드 추가, 거부해야 할 요청의 수용, 사람의 수정 부담**을 본다. 지연은 승인 가능한 후보가 나오기까지 측정한다.
9. jev의 **0.8은 정확도 보장이 아니다.** 보류 비율과 오분류를 함께 보고 임계값을 정하며, 낮은 확률을 보류하는 것만으로 안전성을 주장하지 않는다.
10. 실API 호출과 키 만료·시간초과·뒤늦은 응답 시나리오를 별도 확인해야 한다. 실패 시 기존 규칙·수동 운용을 유지하고, 늦은 결과가 현재 상태에 적용되지 않아야 한다.

## Claude 반영
- 1~10을 모두 수용했다.
- 위험 ②에는 문서 근거를 더했다. [Command Code Provider 문서](https://commandcode.ai/docs/provider)에 따르면 `x-cmd-zdr: 1` 헤더를 붙인 요청은 ZDR 업스트림으로만 처리되고, ZDR 업스트림이 없으면 422로 거부된다. `typesafe/jev`는 ZDR 업스트림이 없다. 그래서 자유 문장은 jev로 보내지 않고, ZDR 헤더를 붙인 chat에만 보낸다. 사용할 chat 모델이 ZDR을 지원하는지는 실호출로 확인해야 한다(현재 키 만료).
