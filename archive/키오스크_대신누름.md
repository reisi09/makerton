# 말로 주문하면 대신 눌러 주는 키오스크 보조기기 (13라운드, 2026-10-31 KST)

> 사용자 반응: Pico Forge에 "대체 뭔 의미가 있는데, 주제가 너무 시사하는 바가 적다."
> GPT-6-Astra(max)는 조건부로 채택했다. 원문: `astra/round13_kiosk.md`

## 0. 한 줄
**키오스크를 바꾸지 않는다. 사람이 말로 주문하면, AI가 화면을 보고 피코 로봇 손가락이 대신 누른다.**
- **시사점**(GPT 문안): "사람이 기계 사용법에 적응하는 대신, 기계가 사람의 의도와 기존 인터페이스 사이를 중재한다."

## 1. 왜 의미가 있나 (원문 확인)

- **해석 한계**(GPT 지적):
  - 직원 주문을 선호한다는 결과는 자동화가 필요하다는 증거가 아니다.
  - 예외 조항이 있다고 이 기기의 법적 적합성이 보장되지는 않는다.
  - 당사자 검증 없이 '접근성 해결'이나 '법 준수'를 주장하지 않는다.

## 2. 왜 지금의 기술 흐름인가
- 화면을 보고 클릭하는 **컴퓨터 사용 에이전트**를 **물리 세계**로 옮긴 형태다. 소프트웨어 연동 없이 기존 기기를 몸으로 조작한다.
- 한국 정부의 피지컬 AI 메가프로젝트(연합뉴스 2026-10-29), Gartner 2026 Physical AI와 같은 흐름이다.

## 3. 피코와 LLM이 꼭 필요한 이유
- **피코**
  - 서보 팔과 스타일러스로 실제 화면을 누른다. 키오스크 소프트웨어를 바꿀 수 없으니 물리적 조작이 유일한 연결 방법이다.
  - 즉시 정지, 동작 범위 제한, '결제' 영역 누름 차단 같은 실행 제어는 모델 밖에서 피코와 코드가 한다.
- **LLM(비전)**
  - 매장마다 다른 화면, 팝업(포인트 적립 등), 옵션 질문(HOT/ICE, 사이즈)을 읽고 다음에 누를 곳을 고른다.
  - 사람에게 확인 질문을 한다.
  - 미리 짠 좌표표로는 화면이 바뀌거나 팝업이 끼면 대응할 수 없다.

## 4. 실호출 실측 (2026-10-31)
- 팝업이 뜬 모의 키오스크 캡처(800×600)를 `deepseek/deepseek-v4-flash-vision-exp`에 넣었다. 4.1초 만에 "건너뛰기"를 골랐고 좌표는 **(496, 258)**였다. 실제 중심 **(494, 255)**와 몇 픽셀 차이다. 이유도 "팝업을 먼저 닫아야 한다"로 맞았다.
- `google/gemini-3.8-flash`는 버튼은 맞혔지만 y좌표가 156px 틀렸다. 그래서 deepseek 비전 모델을 쓴다.
- **검증하지 않은 것**: 카메라로 찍은 실제 화면(원근·반사)과 실제 누름 경로. 위 결과는 캡처 이미지 기준이다(GPT 지적).

## 5. 12시간 MVP (GPT 수정 반영)
- **구성**
  - 고정 웹캠(노트북 또는 폰)
  - 서보 팔 + 정전식 스타일러스. 접지된 도전성 팁이 필요하다[추정].
  - 태블릿에 띄운 제한 메뉴 모의 키오스크(HTML)
  - 비상정지 버튼, LED
- **흐름**: 주문 입력(음성 또는 텍스트) → 화면 캡처 → 비전 LLM이 다음 행동 결정(팝업 처리·옵션 확인 질문) → 좌표 변환 → 피코가 누름 → 다시 캡처해 결과 확인 → 반복 → 결제 직전에 사용자 명시 확인
- **12시간에서 뺄 것**: 여러 기종 대응, 실제 결제, 개인정보 입력
- **음성**: Command Code에는 음성 인식이 없다. 크롬 Web Speech API를 쓰거나 버튼·텍스트로 대신한다[미검증]. 대신하면 '음성 보조기기 완성'이 아니라 '조작 기술 시연'으로 표현한다.
- **역할**
  - 하드웨어: 팔·스타일러스와 보정
  - 펌웨어: 서보 제어와 안전 정지
  - AI·서버: 화면 판단 루프, 확인 대화, 좌표 변환

## 6. 안전·윤리 원칙 (GPT)
1. **사용자 통제**: 명시 승인 없이는 결제를 누르지 못하게 모델 밖 실행 제어로 막는다. 언제든 즉시 중단할 수 있다.
2. **개인정보**: 결제·인증 화면은 촬영하거나 전송하지 않는다. 주문 음성과 화면의 외부 전송은 알리고 동의를 받으며 최소화한다.
3. **선택권과 정직성**: 직원 도움과 취소 경로를 유지한다. 접근성 해결이나 법 준수를 주장하지 않는다.

## 7. 90초 시연
1. "따뜻한 아메리카노 한 잔"이라고 주문한다.
2. 팝업("포인트 적립?")이 뜬다 → AI가 화면을 보고 "건너뛸까요?"라고 확인한다 → 손가락이 '건너뛰기'를 누른다.
3. 옵션 화면에서 "뜨거운 걸로요?"라고 확인한다 → 누른다 → 화면을 다시 보고 장바구니에 담겼는지 확인한다.
4. 결제 직전에 멈추고 "결제할까요?"라고 묻는다. 사람이 승인해야만 누른다. 비상정지 버튼을 누르면 즉시 멈춘다.

## 8. 가장 큰 위험과 플랜 B
- **위험**: 카메라→화면→팔 좌표 보정, 그리고 정전식 터치의 재현성
- **플랜 B**(GPT): 모의 키오스크를 소프트웨어 클릭으로 조작해 대화와 화면 판단 흐름만 시연한다. 이 경우 물리 보조기기가 성공한 것처럼 포장하지 않는다.
