실물 배선, 서보·LED·센서 동작은 검증하지 않았다. 9장 시험 T1~T10을 순서대로 통과시킨다. 키트 안 부품 목록도 확인하지 않았다(3장 확인표).
읽는 순서
  1. 1장에서 무엇을 계산하는지 본다.
  2. 2장 총괄 순서로 역할을 나눈다.
  3. A는 4~5장(설계도·제작), B는 5~6장(배선), C는 7~8장(소프트웨어)을 맡는다.
  4. 9장 시험을 통과시킨다.
  5. 10장 리허설로 마무리한다.

1. 한눈에 보기

무엇을 만드나. 우드락 900×900 위의 십자 사거리 하나다. 실제 강남구 교차로(ICE-ZERO 도로망 노드 1220041600)의 네 갈래를 그대로 옮겼다.

  • 교량인 올림픽로(E)
  • 그늘이 지는 테헤란로(W)
  • 일반 도로인 테헤란로115길(N)과 역삼로107길(S)

맥북이 하는 일. 실제 겨울밤 하나(2025년 시험 구간)를 시간 단위로 재생한다.

  1. ICE-ZERO 예보 모델로 +0·+1·+3·+6시간 지면온도를 예측한다.
  2. 예측값을 동결확률로 바꾼다.
  3. 갈래마다 유효 노면온도와 동결확률을 낸다. 교량은 −2.5°C 가정을 쓰거나, 현장 센서가 있으면 그 값으로 보정한다.
  4. ICE-ZERO 상대 위험 순위(risk_v2)로 우선순위를 정한다.
  5. 예산 안에서 어느 갈래를 어떤 순서로 처리할지 고른다.

Pico가 하는 일. 맥북에 USB로 연결된다.

  • 갈래마다 LED 색으로 위험을 보여 준다.
  • 사람이 승인하면 갈래별 서보 살포기를 순서대로 연다(실제 자동 염수분사시설을 축소한 모형).
  • 교량 시험편의 온도·젖음을 맥북에 보낸다.

사람 승인 3단계

  1. 제보 해석 확인: LLM(Command Code)이 자유 문장 현장 제보를 갈래·예산으로 정리하고, 모호하면 되묻는다. 확인해야 반영된다.
  2. 계획 승인: 엔진이 낸 선정·순서를 사람이 승인하면 갈래 LED가 파랗게 깜박인다.
  3. 출동 승인: 승인된 순서대로 살포기가 하나씩 열린다. 언제든 비상 정지할 수 있다.
원칙
  • 결빙을 확정하지 않는다. 화면에는 '예측 동결확률'과 '상대 우선순위'로 쓴다.
  • LLM은 기기를 조종하지 않는다.
  • 교량 주의 LED는 Pico가 맥북 없이도 켠다.
그림 1. 시스템 구성. 맥북이 계산하고 Pico가 실행한다. 사람이 가운데서 승인한다.

persistence는 '지금 지면온도가 그대로 간다'는 기준선이다. h0은 시차·현재 기상으로 현재 지면온도를 추정하는 값이다.
원래 ICE-ZERO 피처 중 일사·일조는 이 자료에 없어 뺐다(경량 재현판). 그래서 원 발표 수치와 정확히 같지 않다.

계산식

  • 갈래 유효온도 = 예측 지면온도 − 2.5 × 교량(ICE-ZERO 공학 가정). 교량 센서가 있으면 (센서값 − 모델 h0 유효온도)를 모든 시점에 더한다.
  • 동결확률 = 2024년 예측으로 맞춘 isotonic 보정곡선(예측 → 실제 지면온도 ≤ 0일 확률)을 갈래 유효온도에 적용한다(가정).
  • p_max = +1·+3·+6h 동결확률의 최댓값
    • 색: 0.3 미만 초록, 0.6 미만 노랑, 그 이상 빨강
    • 후보: p_max ≥ 0.5이거나 확인된 제보가 있는 갈래
  • 우선순위 = ICE-ZERO risk_v2(강남구 2,189개 도로 상대 순위) + 0.5 × 확인된 제보
    • 후보 중 예산(기본 2) 개를 우선순위 순서로 고른다.
    • 처리 순서도 우선순위 순서다(교차로 하나라 경로 = 순서).
이 수치는 관측소 지면온도 예보다. 갈래별 실제 노면 결빙을 검증한 값이 아니다. 교량 −2.5°C와 보정곡선 적용은 ICE-ZERO의 공학 가정이다.

1-3. 겨울밤 재생 결과(엔진 실제 출력)

밤: 2025-12-07 18시 ~ 다음 날 09시(2025 시험 구간, 모델이 학습하지 않은 해). 엔진이 고른 기본 시연 밤이다(조건: 18시 지면온도 > 0, 다음 날 09시까지 최저 ≤ 0, 점수 = 젖음 + 하강 폭). 18시 지면 6.7°C → 최저 -0.9°C(08:00), 직전 12시간 강수·적설 2.4mm.

  • 첫 출동 권고 21시: 교량 E만(동결확률 0.53). 교량 −2.5°C 가정이 들어간 값이다.

왜 이 순서인가
살포기는 상자·구멍·서보 각도를 실물로 맞춰야 해서 시간이 걸린다. 그래서 1단계에서 한 개를 먼저 완성하고 나머지 세 개를 복제한다. 엔진은 이미 학습되어 있으니 C는 대시보드 흐름과 시리얼 연결을 먼저 확인한다.
시간이 부족하면 줄이는 순서
① 부저 → ② 건물 꾸밈 → ③ 교량 센서(대시보드 수동 값으로 대체) → ④ 살포기 개수(E·W 두 갈래만). 엔진 재생 → 승인 → 살포기 실행은 끝까지 지킨다.

5. 제작 순서

A우드락 (A1~A10)

  1. A1 받침: 2번 우드락에서 900×300 조각과 가로대를 자른다. 바닥 두 조각을 뒤집어 y=600에서 맞대고, 밑면에 2겹 가로대 3개를 붙인다.
  2. A2 이음: 바로 놓고 윗면 이음선을 투명 테이프로 평평하게 덮는다.
  3. A3 먹줄: 연필로 x=375·525, y=375·525(도로), 교량 x 610~790, 하천 x 660~740을 긋는다.
  4. A4 하천·도로: 하천에 파란 종이를 먼저 붙이고, 도로에 회색·검정 종이를 붙인다.
  5. A5 교량: x 610~790, y 355~545에 은박을 붙이고 난간(180×15) 2개를 세운다.
  6. A6 표시: 중앙선(노랑 점선), 횡단보도(흰 테이프 10mm 간격), 갈래 이름 표지를 붙인다.
  7. A7 건물: 앞·옆 벽과 지붕을 붙여 L자 상자 4동을 만들고 북서·남서에 세운다. 남쪽에서 램프를 비추면 W 갈래에 그림자가 진다.
  8. A8 살포기 자리: 도면 1 위치에 살포기 상자(B 담당이 만듦)를 놓을 자리와 미끄럼판 각도를 표시한다.
  9. A9 배선 구멍: 살포기 4곳, 교량 관측부, 주의 LED 옆에 Ø8 구멍을 뚫는다. 받침 가로대 사이 통로로 선이 지나가는지 본다.
  10. A10 꾸밈: 차·나무 등을 둔다. 미끄럼판 아래와 살포 지점은 비워 둔다.

BPico·살포기 (B1~B8)

  1. B1 Pico 2 W에 MicroPython(RPI_PICO2_W)을 굽는다. pico_cross/의 config.py · cross_core.py · main.py · hwtest.py를 올린다.
  2. B2 LED 4개(또는 WS2812 4픽셀)를 연결한다 → T1
  3. B3 서보 1개 + 서보 전용 5V를 연결한다. GND는 공통이다 → T2 서보 각도
  4. B4 살포기 시제품(도면 2): 상자 → 바닥 구멍 → 서보와 덮개 → 미끄럼판. 알갱이를 넣고 hwtest로 '1회분'이 떨어지는지 맞춘다.
  5. B5 나머지 살포기 3개를 복제한다. 신호선은 GP18(N)·GP19(E)·GP20(S)·GP21(W)에 꽂는다.
  6. B6 교량 관측부(도면 3): 물받이 → 시험편 → DS18B20 밀착 → 젖음센서 → 4.7kΩ 풀업 → T3
  7. B7 교량 주의 LED(GP15), 부저(GP17, 선택) → T4
  8. B8 모든 선을 보드 밑 통로로 정리하고 전자부를 보드 동쪽 책상에 고정한다. 맥북 USB를 꽂는다.
전원
  • Pico는 맥북 USB로 켠다.
  • 서보 4개는 서보 전용 5V에서 먹인다(+ 470~1000µF). GND는 Pico와 공통이다.
  • 펌웨어는 한 번에 서보 하나만 움직인다.

Pico 업로드(Thonny)

  1. BOOTSEL을 누른 채 USB를 꽂으면 RP2350 드라이브가 생긴다. Pico 2 W용 UF2(RPI_PICO2_W)를 복사한다.
  2. Thonny 인터프리터를 'MicroPython (Raspberry Pi Pico)'로 맞추고 포트를 고른다. Stop을 누르면 REPL로 들어간다.
  3. pico_cross/의 config.py · cross_core.py · main.py · hwtest.py를 같은 이름으로 Pico에 저장한다. main.py는 전원을 켜면 자동 실행된다.
  4. 배선 시험은 Thonny에서 hwtest.py를 열고 실행한다(F5). 끝나면 Thonny를 닫아야 서버가 포트를 쓸 수 있다.
시리얼 약속(요약)
Pico → 맥: @@TEL {"t_bridge","t_air","wet","wet_raw","warn","busy","up"} 1초마다, @@EVT {"e":"spray_start|spray_done|spray_reject|stopped","seq","arm"}
맥 → Pico: @@LED {"arms":{"N":"risk1|risk2|risk3|plan|done|off",…}}, @@SPRAY {"seq":n,"arm":"E","ms":600}, @@STOP {}
Pico 없이 시연할 때: 서버를 --pico-serial none으로 켜면 출동이 '모의 실행'으로 표시된다. 교량 센서는 대시보드 '수동 값'으로 넣는다.

시험방법합격 기준실패하면
T1 갈래 LED
B		Thonny에서 hwtest.py 실행N→E→S→W 순서로 초록·노랑·빨강·파랑(깜박)·흰색이 바뀐다순서가 틀리면 체인 순서(N,E,S,W)를 확인한다. WS2812가 불안하면 5V 선에 다이오드를 넣거나 LED_MODE='gpio'로 바꾼다
T2 서보·살포기
B		hwtest.py의 서보 순환. 알갱이를 넣고 한 번 열림당 양을 본다열림 60°에서 1회분이 떨어지고, 닫히면 새지 않는다. 다른 서보와 동시에 움직이지 않는다SERVO_OPEN_DEG·SERVO_CLOSED_DEG와 구멍 크기를 고친다. Pico가 리셋되면 서보 전원을 분리하고 콘덴서를 단다
T3 교량 센서
B		main.py 실행 중 Thonny 셸의 @@TEL을 본다. 시험편을 쥐었다 놓고, 적신다t_bridge가 변한다. wet이 젖으면 true다None이면 4.7kΩ 풀업을 확인한다. 부팅 ROM 목록을 보고 PIECE_INDEX를 고친다. WET_THRESHOLD는 마른 값과 젖은 값의 중간으로 둔다
T4 주의 LED
B		냉각팩이나 찬물로 시험편을 1°C 아래로 식히고 적신다맥북 연결과 상관없이 주의 LED가 켜진다. 마르거나 따뜻해지면 3회 뒤 꺼진다WARN_ON_C·FREEZE_C를 시연 온도대에 맞춘다
T5 엔진
C		python3 engine/train.py성능표와 기본 시연 밤 표가 1-2·1-3장과 같게 나온다모델 파일이 없으면 자동으로 학습한다(약 1분). xgboost 오류가 나면 brew install libomp
T6 시리얼
C		Thonny를 닫고 서버를 --pico-serial auto로 켠다대시보드 Pico 링크가 '연결'이고 t_bridge가 1초마다 갱신된다. 갈래 LED가 대시보드 색과 같다Pico가 2개 꽂혀 있으면 auto가 고르지 못한다. 포트를 직접 적는다
T7 재생
C		대시보드에서 기본 밤을 18시부터 ▶로 넘긴다1-3장 표와 같은 시각에 출동 권고와 선정 갈래가 나온다밤을 다시 고르거나 서버를 재시작한다
T8 현장 보정

10. 리허설과 90초 시연

부팅 순서

  1. Pico를 맥북 USB에 꽂고 서보 5V를 연결한다. Thonny는 닫는다.
  2. 서버를 실행한다(키 포함, --pico-serial auto). 대시보드를 열고 'Pico 연결'을 확인한다.
  3. 대시보드 초기화 → 기본 밤 선택 → 살포기에 알갱이 채우기 → 물받이 마른 상태

90초 대본

시간동작말
0~10초보드 전체를 가리킨다실제 강남구 교차로 하나를 옮겼습니다. 동쪽은 올림픽로 교량, 서쪽은 그늘진 테헤란로입니다.
10~25초대시보드에서 기본 밤 18시 → 21시로 넘긴다작년 12월 7일 실제 날씨를 맥북의 ICE-ZERO 모델이 시간마다 예측합니다. 21시, 교량의 동결확률이 먼저 올라 출동 권고가 뜹니다.
25~35초3시로 넘긴다. 제안 E → W(예산 2)네 갈래가 모두 후보인데 제설제는 2회분입니다. ICE-ZERO 위험 순위로 교량(강남구 상위 2.5%)과 그늘 테헤란로(상위 14%)를 고릅니다.
35~50초제보 입력 "테헤란로 쪽 미끄럽대요" → 되묻기 → W 체크 → 확인 → 제안이 W → E로 바뀜LLM이 제보를 정리하는데, 테헤란로는 두 갈래라 되묻습니다. 사람이 확인해야 반영되고, 확인된 제보만 순서를 바꿉니다.
50~60초계획 승인 → LED 파랑 깜박계획을 사람이 승인해야 Pico에 표시됩니다.
60~75초출동 승인 → 살포기가 W → E 순서로 열림Pico가 살포기를 한 번에 하나씩 엽니다. 끝난 갈래는 흰색으로 바뀝니다.
75~85초교량 시험편에 냉각팩 → '현장 보정 사용'교량 센서값이 들어오면 모델의 교량 온도를 현장 값으로 보정합니다. 교량 주의 LED는 Pico가 맥북 없이 켭니다.
85~90초비상 정지 버튼을 가리킨다결빙을 확정하는 게 아니라, 언제 어디부터 처리할지 사람이 빨리 결정하도록 돕습니다.

11. 문제 해결

증상흔한 원인조치
서보가 움직이면 Pico가 리셋된다맥북 USB 전류 부족, 서보 전원 공유서보 전용 5V를 쓰고 GND는 공통, 470~1000µF를 단다. 동시 동작은 코드가 막는다
살포기가 막히거나 샌다구멍 크기, 덮개 틈, 알갱이 습기구멍 12×30을 키우거나 덮개를 넓힌다. 각도를 보정하고 마른 알갱이를 쓴다
LED 색이 이상하거나 꺼짐3.3V 데이터, 전원, 10초 명령 없음DIN 330Ω, 5V 다이오드, GND 공통을 확인한다. 서버 링크를 확인한다(10초 넘게 명령이 없으면 꺼지는 게 정상)
대시보드에 Pico 없음Thonny가 포트 점유, 포트 2개Thonny를 닫는다. --pico-serial /dev/tty.usbmodemXXXX
t_bridge None·85.0풀업 없음, 변환 직후4.7kΩ(DQ↔3V3)을 단다. 85.0은 코드가 버린다
엔진 import 오류(xgboost)libomp 없음brew install libomp(이 맥북은 설치됨)
출동 승인이 눌리지 않음승인 계획 없음, 실행 중계획 승인부터 누른다. 비상 정지 후 다시 한다
살포 하나가 4초 넘게 걸려 중단spray_done 미수신, 큐 가득시리얼 로그에서 EVT를 확인한다. 비상 정지 → 초기화 → 다시 출동한다
LLM 401·빈 응답키 없음, 추론 토큰환경변수를 확인한다(코드는 max_tokens 2000을 이미 씀). 실패하면 규칙 해석으로 진행한다
