읽는 순서
  1. 1장에서 무엇을 계산하는지 본다.
  2. 2장 총괄 순서로 역할을 나눈다.
  3. A는 4~5장(설계도·제작), B는 5~6장(배선), C는 7~8장(소프트웨어)을 맡는다.

  5. 10장 리허설로 마무리한다.

1. 한눈에 보기

무엇을 만드나. 우드락 900×900 위의 십자 사거리 하나다. 실제 강남구 교차로(ICE-ZERO 도로망 노드 1220041600)의 네 갈래를 그대로 옮겼다.

  • 교량인 올림픽로(E)
  • 그늘이 지는 테헤란로(W)
  • 일반 도로인 테헤란로115길(N)과 역삼로107길(S)

맥북이 하는 일. 실제 겨울밤 하나(2025년 시험 구간)를 시간 단위로 재생한다.

  1. ICE-ZERO 예보 모델로 +0·+1·+3·+6시간 지면온도를 예측한다.
  2. 예측값을 동결확률로 바꾼다.
  3. 갈래마다 유효 노면온도와 동결확률을 낸다. 교량은 −2.5°C 가정을 쓰거나, 현장 센서가 있으면 그 값으로 보정한다.
  4. ICE-ZERO 상대 위험 순위(risk_v2)로 우선순위를 정한다.
  5. 예산 안에서 어느 갈래를 어떤 순서로 처리할지 고른다.

Pico가 하는 일. 맥북에 USB로 연결된다.

  • 갈래마다 LED 색으로 위험을 보여 준다.
  • 사람이 승인하면 갈래별 서보 살포기를 순서대로 연다(실제 자동 염수분사시설을 축소한 모형).
  • 교량 시험편의 온도·젖음을 맥북에 보낸다.

사람 승인 3단계

  1. 제보 해석 확인: LLM(Command Code)이 자유 문장 현장 제보를 갈래·예산으로 정리하고, 모호하면 되묻는다. 확인해야 반영된다.
  2. 계획 승인: 엔진이 낸 선정·순서를 사람이 승인하면 갈래 LED가 파랗게 깜박인다.
  3. 출동 승인: 승인된 순서대로 살포기가 하나씩 열린다. 언제든 비상 정지할 수 있다.
원칙
  • 결빙을 확정하지 않는다. 화면에는 '예측 동결확률'과 '상대 우선순위'로 쓴다.
  • LLM은 기기를 조종하지 않는다.
  • 교량 주의 LED는 Pico가 맥북 없이도 켠다.

예보 성능(2025년 시험 구간, 학습은 2020~2024)

{{METRICS_TABLE}}

persistence는 '지금 지면온도가 그대로 간다'는 기준선이다. h0은 시차·현재 기상으로 현재 지면온도를 추정하는 값이다.
원래 ICE-ZERO 피처 중 일사·일조는 이 자료에 없어 뺐다(경량 재현판). 그래서 원 발표 수치와 정확히 같지 않다.

계산식

  • 갈래 유효온도 = 예측 지면온도 − 2.5 × 교량(ICE-ZERO 공학 가정). 교량 센서가 있으면 (센서값 − 모델 h0 유효온도)를 모든 시점에 더한다.
  • 동결확률 = 2024년 예측으로 맞춘 isotonic 보정곡선(예측 → 실제 지면온도 ≤ 0일 확률)을 갈래 유효온도에 적용한다(가정).
  • p_max = +1·+3·+6h 동결확률의 최댓값
    • 색: 0.3 미만 초록, 0.6 미만 노랑, 그 이상 빨강
    • 후보: p_max ≥ 0.5이거나 확인된 제보가 있는 갈래
  • 우선순위 = ICE-ZERO risk_v2(강남구 2,189개 도로 상대 순위) + 0.5 × 확인된 제보
    • 후보 중 예산(기본 2) 개를 우선순위 순서로 고른다.
    • 처리 순서도 우선순위 순서다(교차로 하나라 경로 = 순서).
이 수치는 관측소 지면온도 예보다. 갈래별 실제 노면 결빙을 검증한 값이 아니다. 교량 −2.5°C와 보정곡선 적용은 ICE-ZERO의 공학 가정이다.

5. 제작 순서

A우드락 (A1~A10)

  1. A1 받침: 2번 우드락에서 900×300 조각과 가로대를 자른다. 바닥 두 조각을 뒤집어 y=600에서 맞대고, 밑면에 2겹 가로대 3개를 붙인다.
  2. A2 이음: 바로 놓고 윗면 이음선을 투명 테이프로 평평하게 덮는다.
  3. A3 먹줄: 연필로 x=375·525, y=375·525(도로), 교량 x 610~790, 하천 x 660~740을 긋는다.
  4. A4 하천·도로: 하천에 파란 종이를 먼저 붙이고, 도로에 회색·검정 종이를 붙인다.
  5. A5 교량: x 610~790, y 355~545에 은박을 붙이고 난간(180×15) 2개를 세운다.
  6. A6 표시: 중앙선(노랑 점선), 횡단보도(흰 테이프 10mm 간격), 갈래 이름 표지를 붙인다.
  7. A7 건물: 앞·옆 벽과 지붕을 붙여 L자 상자 4동을 만들고 북서·남서에 세운다. 남쪽에서 램프를 비추면 W 갈래에 그림자가 진다.
  8. A8 살포기 자리: 도면 1 위치에 살포기 상자(B 담당이 만듦)를 놓을 자리와 미끄럼판 각도를 표시한다.
  9. A9 배선 구멍: 살포기 4곳, 교량 관측부, 주의 LED 옆에 Ø8 구멍을 뚫는다. 받침 가로대 사이 통로로 선이 지나가는지 본다.
  10. A10 꾸밈: 차·나무 등을 둔다. 미끄럼판 아래와 살포 지점은 비워 둔다.

BPico·살포기 (B1~B8)

  1. B1 Pico 2 W에 MicroPython(RPI_PICO2_W)을 굽는다. pico_cross/의 config.py · cross_core.py · main.py · hwtest.py를 올린다.
  2. B2 LED 4개(또는 WS2812 4픽셀)를 연결한다 → T1
  3. B3 서보 1개 + 서보 전용 5V를 연결한다. GND는 공통이다 → T2 서보 각도
  4. B4 살포기 시제품(도면 2): 상자 → 바닥 구멍 → 서보와 덮개 → 미끄럼판. 알갱이를 넣고 hwtest로 '1회분'이 떨어지는지 맞춘다.
  5. B5 나머지 살포기 3개를 복제한다. 신호선은 GP18(N)·GP19(E)·GP20(S)·GP21(W)에 꽂는다.
  6. B6 교량 관측부(도면 3): 물받이 → 시험편 → DS18B20 밀착 → 젖음센서 → 4.7kΩ 풀업 → T3
  7. B7 교량 주의 LED(GP15), 부저(GP17, 선택) → T4
  8. B8 모든 선을 보드 밑 통로로 정리하고 전자부를 보드 동쪽 책상에 고정한다. 맥북 USB를 꽂는다.
전원
  • Pico는 맥북 USB로 켠다.
  • 서보 4개는 서보 전용 5V에서 먹인다(+ 470~1000µF). GND는 Pico와 공통이다.
  • 펌웨어는 한 번에 서보 하나만 움직인다.

11. 문제 해결

증상흔한 원인조치
서보가 움직이면 Pico가 리셋된다맥북 USB 전류 부족, 서보 전원 공유서보 전용 5V를 쓰고 GND는 공통, 470~1000µF를 단다. 동시 동작은 코드가 막는다
살포기가 막히거나 샌다구멍 크기, 덮개 틈, 알갱이 습기구멍 12×30을 키우거나 덮개를 넓힌다. 각도를 보정하고 마른 알갱이를 쓴다
LED 색이 이상하거나 꺼짐3.3V 데이터, 전원, 10초 명령 없음DIN 330Ω, 5V 다이오드, GND 공통을 확인한다. 서버 링크를 확인한다(10초 넘게 명령이 없으면 꺼지는 게 정상)
대시보드에 Pico 없음Thonny가 포트 점유, 포트 2개Thonny를 닫는다. --pico-serial /dev/tty.usbmodemXXXX
t_bridge None·85.0풀업 없음, 변환 직후4.7kΩ(DQ↔3V3)을 단다. 85.0은 코드가 버린다
엔진 import 오류(xgboost)libomp 없음brew install libomp(이 맥북은 설치됨)
출동 승인이 눌리지 않음승인 계획 없음, 실행 중계획 승인부터 누른다. 비상 정지 후 다시 한다
살포 하나가 4초 넘게 걸려 중단spray_done 미수신, 큐 가득시리얼 로그에서 EVT를 확인한다. 비상 정지 → 초기화 → 다시 출동한다
LLM 401·빈 응답키 없음, 추론 토큰환경변수를 확인한다(코드는 max_tokens 2000을 이미 씀). 실패하면 규칙 해석으로 진행한다
