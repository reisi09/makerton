1. 한눈에 보기

무엇을 만드나. 우드락 1800×600mm 위의 왕복 4차로 도로다. 바깥 차로 두 개를 잇는 검정 유도선을 Pico 라인트레이서 제설차가 돈다. 도로는 방향 2 × 구간 4 = 8칸으로 나눈다(S1 일반 · S2 교량 · S3 그늘 · S4 일반). 제설차는 바닥 막대를 세어 지금 칸을 알고, 사람이 승인한 칸에서만 모형 제설제를 뿌린다.

ICE-ZERO와의 연결. 원래 ICE-ZERO는 "어느 도로가 위험한가 → 예산 안에서 어디부터 → 어떤 순서로"를 계산한다. 모형에서는 8칸 점수 → 제설제 n회분 안에서 칸 선택 → 루프 순서 실행으로 같은 흐름을 작게 보여 준다.

사람 승인 3단계

  1. 제보 해석 확인: LLM이 자유 문장 제보를 칸·예산으로 정리하고, 모호하면 되묻는다. 담당자가 고쳐서 확인해야 반영된다.
  2. 계획 승인: 코드가 계산한 제안을 담당자가 승인하면 칸 LED가 바뀌고 계획이 제설차로 간다.
  3. 출동 승인: 제설차가 같은 계획을 받았다고 응답한 뒤에만 출발 명령을 보낼 수 있다.
원칙
  • LLM은 차를 조종하지 않는다.
  • 안전 정지(초음파·버튼·길 잃음)와 교량 주의 LED는 Pico가 로컬에서 즉시 처리한다.
  • 화면과 발표에서 '결빙 확정'이라고 말하지 않는다. '관측 주의'와 '상대 우선순위'라고 말한다.
그림 1. 시스템 구성. 노트북과 제설차는 같은 휴대폰 핫스팟(2.4GHz)에 붙는다. 보드 Pico는 노트북 USB에 꽂는다.

4. 우드락 설계도

도면 1. 전체 평면도 (단위 mm)

우드락 2장을 x=900에서 이어 붙인다. 바깥 차로 두 개를 따라 유도선(검정 19mm)을 붙이고 양 끝은 반지름 190 원호로 잇는다. 빨간 점선은 차체가 지나가는 폭(유도선 ±70)이며, 이 안에는 아무것도 두지 않는다. L1~L8은 칸 LED 기둥이고 체인 순서와 같다.

도면 2. 바닥 표식 상세와 좌표표

표식이 하는 일
제설차는 세 센서가 모두 검정을 보면 막대 1개로 센다. 막대 사이 간격이 GROUP_GAP_MS보다 짧으면 같은 묶음이다. 묶음 크기 1 = SEG(구간 경계), 2 = END(직선 시작·끝), 3 = HOME(정차)이다.
한 바퀴: HOME 출발 → END → SEG×3 → END → (동쪽 회차) → END → SEG×3 → END → (서쪽 회차) → HOME 정지.

5. 제작 순서

A우드락 보드 (A1~A14)

  1. A1 받침: 보드 2장을 뒤집어 x=900에서 맞댄다. 밑면에 2겹(10mm) 가로대 3개를 본드나 양면테이프로 붙인다. 위치는 x 250~350 · 850~950 · 1450~1550.
  2. A2 이음: 바로 놓고 윗면 이음선을 투명 테이프로 평평하게 덮는다. 단차가 있으면 차가 튄다.
  3. A3 기준선: 연필로 y=110, y=490(유도선), x=330·615·900·1185·1470(구간 경계)을 표시한다.
  4. A4 원호: (330,300)·(1470,300)에 압정을 꽂고 실 190mm로 반원을 그린다. 서쪽은 왼쪽 반원, 동쪽은 오른쪽 반원이다.
  5. A5 교량: x 615~900 전체에 호일을 붙이고 주름을 편다. 호일은 센서에 흰색처럼 보인다. 유도선은 그 위에 붙인다.
  6. A6 차선(선택): 밝은 색만 쓴다. y=150·450 점선, y=295·305 노랑. S3 그늘은 유도선 근처를 어둡게 칠하지 않는다(센서가 검정으로 읽음). 그늘은 방음벽과 램프로 표현한다.
  7. A7 유도선: 직선부부터 붙인다. 원호는 30~40mm 조각을 조금씩 겹쳐 연필선을 따라 붙인다. 손톱으로 눌러 들뜬 곳을 없앤다.
  8. A8 막대: 도면 2 좌표표대로 70mm 조각 17개(END 8 · SEG 6 · HOME 3)를 붙인다.
  9. A9 점검: 유도선 폭과 연속성, 막대 간격 30mm(END), 표면 먼지를 확인한다. → B에게 트랙 넘김
  10. A10 구멍: Ø8(시험편 2곳, 주의 LED 1곳), Ø6(LED 기둥 8곳). 연필이나 드라이버로 뚫는다. 차체 통과 폭 밖인지 확인한다.
  11. A11 칸 LED: 기둥 8개를 가장자리에 세운다. L1(U1)→L4(U4)는 아래쪽 서→동, L5(D4)→L8(D1)은 위쪽 동→서 순서로 체인을 잇고 밑면 통로로 Pico #1까지 뺀다.
  12. A12 교량 관측부: 물받이 뚜껑 → 금속 시험편 → DS18B20을 알루미늄·종이테이프로 밀착 → 젖음센서 기판 → 선을 구멍으로 뺀다(도면 5).
  13. A13 주의 LED와 방음벽: 주의 LED는 중앙선 (645,300)에 세운다. 방음벽은 S3 가장자리에 세우고 삼각 받침을 붙인다.
  14. A14 꾸밈: 차고지 표지(서쪽 원호 안쪽), 1차로 통제판(상행 1차로, y 320~390), 장난감 차. 마지막으로 빨간 점선 안이 비어 있는지 본다.

B제설차 (B1~B10)

  1. B1 섀시에 모터·바퀴·캐스터를 단다. 바퀴가 바닥에 고르게 닿는지 본다.
  2. B2 라인센서: 앞쪽 밑면에 3개, 중심 간 18mm, 바닥에서 5~8mm, 바퀴 축보다 30~40mm 앞에 단다. 모듈 나사를 돌려 흰 바닥에서 꺼지고 검정 테이프에서 켜지게 맞춘다.
  3. B3 위판에 Pico #2, 드라이버, 브레드보드, 배터리 홀더, 보조배터리를 고정한다. 무게는 바퀴 축 근처로 모은다.
  4. B4 배선(도면 7): 신호선 → 전원선 순서로 연결한다. 전원을 넣기 전에 GND가 모두 하나로 이어졌는지 확인한다.
  5. B5 초음파(선택): 앞쪽 30~40mm 높이. ECHO는 1kΩ/2kΩ 분압을 거쳐 GP3로 간다.
  6. B6 살포통(도면 4-d): 상자를 접착해 뒤쪽에 달고, 서보 혼에 덮개를 붙인다. 닫힌 상태에서 알갱이가 새지 않아야 한다.
  7. B7 경광 LED(GP17), 버튼(GP21↔GND)을 단다.
  8. B8 업로드: config.py를 고친 뒤 파일을 올린다(5장 C6).
  9. B9 T1 모터 방향 → T2 센서(6장)를 한다.
  10. B10 트랙에서 T3~T9를 순서대로 한다.
전원 주의
  • 모터 전원(AA×4)은 드라이버 VM에만 넣는다. Pico는 USB 보조배터리로 켠다(VBUS=5V가 생겨 초음파·서보 전원으로 쓴다).
  • Pico 핀은 3.3V다. 5V 신호를 바로 넣지 않는다.

9. 단계별 시험·보정 (T1~T14)

위에서부터 하나씩 통과시킨다. 앞 단계를 통과하지 못하면 다음 단계로 가지 않는다. 각 시험의 출력과 결과를 사진이나 메모로 남기면 발표 근거가 된다.

시험방법합격 기준실패하면
T1 모터 방향
B		바퀴를 띄운 채 pico_car/hwtest.py(Thonny에서 열고 실행)를 실행한다(왼쪽·오른쪽 앞/뒤 각 1초).'왼쪽 앞'에서 왼쪽 바퀴가 앞으로 돈다. 오른쪽도 같다.방향이 반대면 config LEFT_INVERT·RIGHT_INVERT를 바꾼다. 안 돌면 STBY(GP9)가 HIGH인지, VM에 배터리가 연결됐는지, GND가 공통인지 본다.
T2 라인센서
B		config.DIAG=True로 올리면 주행하지 않고 200ms마다 L·C·R, 거리, 버튼을 출력한다. 센서를 흰 바닥과 검정 테이프 위에 각각 둔다.흰 바닥 = (0,0,0), 테이프 위 = 해당 센서 1.모듈 나사로 감도를 맞춘다. 반대로 나오면 BLACK_LEVEL=0. 값이 흔들리면 높이를 5~8mm로 낮춘다.
T3 직선 추종
B		직선부에 차를 놓고 버튼으로 시험 주행을 시작한다(계획이 없으면 살포 없이 한 바퀴).1m 이상 선을 벗어나지 않는다. 흔들림이 차폭 절반 이하.지그재그가 심하면 SOFT_TURN을 낮춘다. 느리게 벗어나면 SOFT_TURN을 올린다. 전체적으로 불안하면 BASE_SPEED를 낮춘다(0.45~0.65).
T4 회차 원호
B		원호에서 시작해 반 바퀴를 돈다.R190 원호를 벗어나지 않고 직선으로 들어간다.HARD_TURN을 올리거나 BASE_SPEED를 낮춘다. 바깥으로 밀리면 센서를 바퀴 축에서 더 앞으로 옮긴다.
T5 막대 묶음
B		LOG_MARKERS 출력(막대 간격 ms, 묶음 크기)을 Thonny로 보며 한 바퀴 돈다.END=2, SEG=1, HOME=3으로 읽힌다.END가 SEG 2개로 읽히면 GROUP_GAP_MS를 늘린다(END 막대 간격 ms의 약 1.5배). 막대를 놓치면 속도를 낮추거나 BAR_CONFIRM을 1로 바꾼다.
T6 한 바퀴 칸 추적
B		HOME에서 출발해 한 바퀴 돈다.칸이 U1→U2→U3→U4→(회차)→D4→D3→D2→D1→HOME 순서로 찍히고 HOME에서 정지한다. 3회 연속.T5로 돌아간다. 출발하자마자 묶음이 생기면 차를 HOME 막대 바로 뒤(서쪽 원호)에 놓는다.
T7 살포
B		pico_car/hwtest.py(Thonny에서 열고 실행)로 서보 열기·닫기를 확인한 뒤, 계획 U2,D3을 넣고 한 바퀴 돈다.U2와 D3에서만 1회씩 열린다. 닫혔을 때 새지 않는다.각도는 SERVO_OPEN_DEG(기본 60)·SERVO_CLOSED_DEG(0)로, 열림 시간은 SALT_MS(600)로 보정한다. 서보가 떨리면 470µF를 달고 전원을 확인한다.
시험방법합격 기준실패하면
T8 초음파 정지
B		주행 중 손을 차 앞 10cm에 댄다.즉시 정지(HOLD_OBS)하고, 손을 치우면 0.5초 뒤 다시 간다.DIAG로 거리를 본다. 0이나 None이면 ECHO 분압·5V를 확인한다. 바닥을 읽으면 센서를 위로 기울인다.
T9 버튼
B		주행 중 짧게 누른다 → 다시 누른다.HOLD_CMD로 정지했다가 재개한다.배선(GP21↔GND)을 확인한다.
T10 Wi-Fi·UDP
BC		차 config에 핫스팟과 SERVER_IP(노트북 IP)를 넣는다. 서버를 켜면 대시보드 '제설차' 칸에 hello가 보인다.마지막 수신이 1~2초마다 갱신된다.2.4GHz인지, 노트북 IP가 바뀌지 않았는지, 방화벽 허용인지 본다. 안 되면 USB 계획 + 버튼 출발로 시연한다.
T11 보드 센서
AC		Thonny에서 보드 main.py 출력의 @@TEL을 본다. 시험편을 손으로 쥐었다 놓고, 물을 묻힌다.t_piece가 변한다. wet가 젖으면 true, 마르면 false가 된다.DS18B20이 None이면 4.7kΩ 풀업과 배선을 본다. 부팅 로그 ROM 순서를 보고 PIECE_INDEX를 고친다. wet는 WET_THRESHOLD와 WET_WHEN_LOW로 보정한다.
T12 칸 LED·주의 LED
AC		서버를 --board-serial auto로 켜고 대시보드에서 제안을 승인한다. 냉각팩이나 찬물로 시험편을 식힌다.승인 칸이 파랗게 깜박이고 나머지는 위험색이다. 조건이 되면 주의 LED가 바로 켜진다.LED 순서가 틀리면 체인 순서(L1=U1 …)를 확인한다. WS2812가 불안정하면 5V에 다이오드를 넣거나 LED_MODE='gpio'로 바꾼다.
T13 전체 흐름
전원		대시보드: 제보 입력 → 해석 확인 → 계획 승인 → 출동 승인 → 주행·살포 → HOME 정차. 비상 정지와 재개도 한 번씩 한다.승인된 칸에만 뿌리고, 대시보드 살포 표시와 칸 LED가 일치한다.대시보드 이벤트 로그와 server/events.jsonl에서 어디서 멈췄는지 본다(plan ack, go ack, marker).
T14 LLM 해석
C		키를 넣고 서버를 켠다. "다리 위 동쪽으로 가는 쪽 미끄러워요", "그늘진 데 미끄럽대요"(방향 없음)를 입력한다.첫 문장 → U2. 둘째 문장 → 방향을 되묻는 질문. 규칙 해석과 나란히 보인다.키, 네트워크, 응답 시간(약 5~7초)을 확인한다. 실패하면 서버가 규칙 해석으로 대체하고 화면에 이유를 표시한다.

증상흔한 원인조치
차가 지그재그로 흔들린다보정이 과함, 속도가 빠름SOFT_TURN·HARD_TURN을 낮추고 BASE_SPEED를 낮춘다. 센서를 바퀴 축 가까이 옮겨 본다.
원호에서 바깥으로 빠진다회전 부족, 속도 과다HARD_TURN을 올리고 BASE_SPEED를 낮춘다. 센서를 축보다 더 앞에 둔다.
END가 SEG 2개로 읽힌다느린 속도에서 막대 간격 시간이 GROUP_GAP_MS보다 길다LOG_MARKERS의 간격 ms를 보고 GROUP_GAP_MS를 그 약 1.5배로 둔다. SEG 사이 간격(수 초)보다는 짧아야 한다.
막대를 놓친다센서가 높음, 속도 빠름, 테이프 들뜸높이 5~8mm, BASE_SPEED를 낮춘다. 막대를 다시 붙인다.
출발하자마자 정지HOME 막대 위에서 출발, 초음파가 바닥이나 물체를 봄차를 HOME 막대 바로 뒤에 놓는다. 초음파 각도를 바꾸고 STOP_CM을 확인한다.
살포통이 새거나 막힌다덮개 틈, 알갱이 습기덮개를 키우고 각도를 보정한다. 마른 알갱이를 쓴다.
대시보드에 차가 안 보인다SERVER_IP 틀림, 5GHz, 방화벽IP를 다시 확인하고 2.4GHz인지 본다. python3 들어오는 연결을 허용한다. 시리얼 출력에서 Wi-Fi 연결 로그를 본다.
출동 버튼이 안 눌린다차가 같은 계획을 ack하지 않음, 차가 IDLE이 아님계획 승인을 다시 누른다. 차 상태를 초기화(중단)하고 HOME에 놓는다.
보드 시리얼 연결 실패Thonny가 포트를 잡고 있음, Pico가 2개 꽂힘Thonny를 닫는다. --board-serial에 포트를 직접 적는다.
DS18B20 값 없음·85.0풀업 없음, 변환 직후 값4.7kΩ(DQ↔3V3)을 단다. 85.0은 코드가 무시한다. 배선을 짧게 한다.

계획 점수식

점수 = 3.0 × 확인된 제보 + 2.0 × 교량 관측 주의 + 1.5 × 구조물(교량) + 1.0 × 그늘
이미 뿌린 칸은 0점이다(뿌린 뒤 새로 확인된 제보가 있으면 다시 점수를 받는다). 점수가 0보다 큰 칸을 (점수 높은 순, 루프 순서) 기준으로 예산 개수만큼 고르고, 실행은 루프 순서(U1→U4→D4→D1)로 한다.
색: 0 = 초록, 0 초과 2.5 미만 = 노랑, 2.5 이상 = 빨강. 상대 우선순위이며 결빙확률이 아니다.
