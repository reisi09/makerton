## 2. 등굣길 위험 조사관
**이야기**: 학교 앞 횡단보도를 두고 보호자들이 "오른쪽 트럭 때문에 차가 안 보여요", "아니에요, 왼쪽 차가 빨라서 위험해요"라고 서로 다르게 말한다. 어느 쪽에서, 언제, 무엇 때문에 위험한지 측정한 사람은 없다.

**LLM의 고리 (가설 → 실험 → 측정 → 수정)**:
1. 입력은 성인이 검수한 비식별 제보다. 이름, 학년·반, 얼굴, 번호판은 넣지 않는다.
2. LLM이 경쟁 가설 2~3개를 세우고, 가설마다 **예상 관측과 기각 조건**을 적는다.
   - 예: "우측 정차 구역이 점유되면, 아이 눈높이에서 오른쪽 차로를 보는 시야선이 끊긴다. 점유 중에도 시야선이 이어지면 기각한다."
3. LLM이 허용된 실험 목록(노드·구역·시간 창·길이)에서 가설을 가장 잘 구별할 실험 하나를 고른다. 사람이 승인한다.
4. 피코가 측정해 요약을 돌려준다. LLM은 예상과 대조해 각 가설을 유지·기각·보류로 정하고 다음 실험을 제안한다.
5. 결론이 나면 브리핑 초안 두 가지를 만든다. 학생용 횡단 수칙과 학교·구청용 측정 근거다. 위반은 판정하지 않으며, 사람이 승인한 뒤에 쓴다.

**피지컬 (피코 1대, 모형)**:
| 측정·동작 | 부품 | 비고 |
|---|---|---|
| 횡단보도 좌·우 정차 구역 점유 | HC-SR04 2개 | |
| 정지한 대기 보행자 | 거리 센서(HC-SR04 등) | PIR은 정지한 대상을 잘 못 잡아 쓰지 않는다(GPT 보완) |
| 아이 눈높이의 좌·우 시야선 차단 | 적외선 발광·수광 쌍 2개 | 모형 차량이 시야선을 가리는지 직접 측정한다(GPT 보완) |
| 접근 차량 | 적외선 빔 쌍 | 있음·시각만 기록한다. 속도를 위반 근거로 쓰지 않는다 |
| 실시간 경고 | 운전자용 '보행자 대기' LED, 보행자용 '시야 가림' LED | **로컬 규칙**: 대기 보행자 + 시야선 차단 → 즉시 점등. LLM 응답을 기다리지 않는다 |

- 피코가 2대면 반대편 보도 노드를 따로 둔다.

**LLM이 꼭 필요한지 확인하는 방법**: 같은 모형 반례(상충 제보, 부분 정보, 측정이 예상과 어긋나는 경우)를 고정 규칙과 LLM에 똑같이 준다.
- 고정 규칙의 예: "제보에 '우측'이 있으면 우측을 측정한다."
- 비교할 항목: 맞는 가설에 이르기까지의 실험 횟수, 잘못된 결론, 근거 없는 주장, 사람의 수정량
- 차이가 없으면 LLM 필수성 주장을 철회한다. 측정하기 전에는 수치를 쓰지 않는다.

**LLM이 하지 않는 일**: 위반·책임 판정, 실시간 경고 결정, 측정 없는 결론, 모형 결과를 실제 도로의 사고 위험으로 일반화하는 것

**개인정보**:
- 자유 문장은 `x-cmd-zdr: 1`을 붙인 chat에만 보낸다. [Command Code 문서](https://commandcode.ai/docs/provider)상 ZDR 업스트림이 없는 모델은 422로 거부된다.
- `typesafe/jev`는 ZDR을 지원하지 않으므로 문장을 보내지 않는다.
- `deepseek/deepseek-v4.1-flash`는 `x-cmd-zdr: 1`을 붙인 요청에 HTTP 200으로 응답했다(2026-10-31 실호출). 모델을 바꾸면 다시 확인한다.

**12시간 계획**:
- 3인이 병렬로 나눈다: 모형·센서 / 로컬 경고·측정 실행기 / LLM 가설·실험 루프
- 시간 배분: 모형·센서 3h, 로컬 경고·측정 2h, LLM 루프 3h, 반례 시나리오·규칙 비교 2h, 발표 1h, 예비 1h
- 구현을 보장하는 일정이 아니라 계획이다.

**90초 시연**:
1. 0~15초: 상충 제보 2개 입력
2. 15~35초: LLM이 가설 2개, 예상 관측·기각 조건, 구별 실험 1개를 제안 → 승인
3. 35~55초: 장난감 트럭을 우측 정차 구역에 놓고 아이 모형을 대기시킨다. 오른쪽 시야선이 끊기고 경고 LED가 즉시 켜진다(로컬 규칙).
4. 55~75초: 측정 결과로 가설 1을 유지한다. 가설 2는 "속도는 측정하지 않음"으로 보류하고, 다음 실험을 제안한다.
5. 75~90초: 학생용 수칙과 학교·구청용 측정 근거 초안을 보여 준다. 인터넷을 끊어도 경고 LED는 계속 동작한다.

**위험**:
- 주정차와 인접해 '다른 주제'로 느껴지지 않을 수 있다.
- 모형 측정은 실제 도로를 대표하지 않는다.
- LLM 필수성은 비교 실험 전까지 미입증이다.
- LLM 응답은 실시간용이 아니다. 실호출에서 chat 제안은 4.7~7.2초(추론 `low`) 걸렸다.

## 2-1. 피코 WH와 LLM은 어떻게 연결되나
- 피코 WH는 RP2040 마이크로컨트롤러(SRAM 264KB)라서 LLM을 기기 안에서 돌리지 않는다. LLM은 노트북 중계 서버가 Command Code API로 부른다. API 키는 노트북 환경변수에만 둔다.

```
[피코 WH: 센서·LED] ──USB '@@REQ/@@RES'──> [노트북 중계 서버: 상태·실험 관리, 대시보드 승인] ──HTTPS──> [Command Code chat LLM]
   즉시 경고(로컬 규칙)                              ↑ 사람이 가설·실험·브리핑 승인
```

| 담당 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 피코 | 센서 읽기, 대기 보행자 + 시야선 차단이면 경고 LED 즉시 점등, 승인된 측정 명령 실행·집계 | LLM 호출, 키 보관 |
| 노트북 중계 서버 | 제보·측정 결과 보관, 허용 실험 목록 검사, LLM 호출, 승인 화면 | 실시간 경고 결정 |
| LLM(chat) | 경쟁 가설·예상 관측·기각 조건, 구별 실험 선택, 결과 해석, 브리핑 초안 | 위반 판정, 경고 결정, 측정 없는 결론 |
| 사람 | 제보 검수·비식별, 실험·브리핑 승인 | |

한 번의 고리(메시지는 설계 예시이며 아직 구현하지 않았다):
1. 피코 → 노트북(1초마다 상태 요약): `{"device":"crosswalk","state":{"stop_right":true,"stop_left":false,"waiting":true,"sight_left_blocked":false,"sight_right_blocked":true}}`
2. 노트북이 검수된 제보, 허용 실험 목록, 최근 상태를 chat에 보낸다. 응답 예:
   `{"hypotheses":[{"id":"H1","claim":"우측 정차가 오른쪽 시야를 가림","expect":"stop_right와 sight_right_blocked가 함께 켜짐","reject_if":"stop_right 중에도 sight_right 연결"}],"experiment":{"zones":["stop_right","sight_right","waiting"],"duration_s":60}}`
   중계 서버가 실험이 허용 목록 안에 있는지 검사한 뒤 대시보드에서 승인받는다.
3. 노트북 → 피코: `@@RES {"cmd":"measure","exp_id":7,"zones":[...],"duration_s":60}`. 피코가 60초 동안 각 상태의 지속 시간과 동시 발생 시간을 세서 돌려준다.
   예: `{"exp_id":7,"result":{"stop_right_s":42,"sight_right_blocked_s":40,"overlap_with_waiting_s":35}}`
4. 노트북이 결과와 가설을 다시 chat에 보낸다. 응답 예: `{"H1":"유지","H2":"보류(속도 미측정)","next_experiment":{...}}`. 결론이 나면 브리핑 초안을 만들고 승인을 받는다.

왜 이렇게 나누나:
- 경고는 기기에서 바로 나와야 한다. 2026-10-31 실호출에서 jev 판단은 0.6~2.2초, chat 제안은 4.7~7.2초(추론 `low`) 걸렸다. 스타터의 chat 시간 제한은 30초다.
- 키를 기기에 두지 않는다. 인터넷이 끊겨도 경고는 계속 동작한다.
- 현재 스타터의 피코 루프는 0.5초 주기다. 경고 반응을 더 빠르게 하려면 줄인다.

스타터에서 쓸 것과 새로 만들 것:
- 그대로 쓴다: USB `@@REQ/@@RES` 통신(`serial_bridge.py`), 대시보드 승인, `cmd_id` 중복 방지, chat 호출 함수(`call_api`)
- 새로 만든다:
  - 피코: 적외선 시야선·거리 센서 `read_state()`, `measure` 명령 실행기, 결과 보고 필드(현재 `@@REQ`는 `/decide` 판단 요청용이다)
  - 중계 서버: 가설·실험 루프 프롬프트, 허용 실험 검사, ZDR 헤더
- 일반 라즈베리파이(4·5 등 리눅스 보드)를 쓸 수 있다면 노트북 대신 중계 서버를 돌릴 수 있다. LLM은 그래도 Command Code API로 부른다. 키트에 들어 있는지는 확인하지 못했다(포스터에는 피코 WH만 적혀 있다).

## 3. 근거 요건을 완화할 때의 후보(2~4순위, GPT 제안)
- 상세: `astra/round8_topics.md`. 세 후보 모두 LLM이 대안·가설을 만들고 실물 반례로 수정하는 구조라서 LLM 역할은 강하다.
- 근거는 신청형 민원이 섞인 부서 접수량이나 단년 키워드뿐이다. **'최근 5년 이상 수원 민원 근거를 충족한 후보'로 제시하면 안 된다**(양측 합의).
