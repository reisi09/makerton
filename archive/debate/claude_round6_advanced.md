# Claude 6라운드: 비초보 팀 기준 재평가 (독립 초안 → GPT 최종 판정 반영)

## 1. 수정한 전제
- 사용자가 확인한 것은 **초보팀이 아니라는 것**이다. C++·TinyML·기구 제작 숙련도와 추가 피코 확보까지 확인한 것은 아니다.
- 12시간 제작 제약은 유지한다. 기초 학습을 줄이는 대신 다중 장치 통합, 조치 후 재측정, 실패 상황 검증에 시간을 배정한다.
- 추천 설계는 **독립된 역할의 피코 2노드**로 잡되, 보드 2대 확보를 선행 조건으로 명시한다. 보드별 USB 중계·고유 ID와 승인 기능은 스타터에 있지만 이 이동 시나리오의 펌웨어·실물 통합은 아직 구현·검증하지 않았다.
- 새 점수를 붙여 순위를 억지로 바꾸지 않는다. 기존 점수는 5라운드 당시 범위의 평가로 남기고, 사용자에게는 기술적 차별성과 남은 구현을 기준으로 추천한다.

## 3. 기존 5개의 기술적 승부처(새 순위·점수 아님)

## 4. 플래그십: 1+3 결합 「막힌 길부터 버스 탑승까지: 교통약자 이동 인계 시스템」
- **추천 이유**: 보도 안내와 승차 인계를 한 사람의 이동으로 연결한다. 기술적 핵심은 부품 수가 아니라 서로 다른 노드가 같은 이동 건을 추적하고, 낡은 계획과 잘못된 완료를 막는 것이다.
- **노드**: ① 보도 노드(USB): 통로 A/B 초음파 2 + 서보 화살표, ② 정류장 노드(USB): 요청·수락·탑승 확인 버튼 + 정차면 초음파 + 적외선 통과 센서. 보드 2대 확보가 선행 조건이다. 세 번째 노드·TinyML·자유 경로 탐색·실시간 버스 API는 이 통합 시연 범위에서 제외한다.
- **상태 전이(설계, 미구현)**: 요청→경로 제안→승인→이동 확인→승차 요청→수락→정차면 확보→통과·당사자 확인→완료. 노트북 호스트 한 곳만 상태 전이를 확정한다. 재차단·센서 오류·노드 보고 끊김은 보류하며, 재계획은 승인 후 사전 지정 경로 선택으로 제한한다. 정차면 확보는 센서 관측과 담당자 현장 확인을 함께 쓰고, 노드 경고 단계와 이동 완료 상태는 별도로 관리한다.
- **AI 역할**: 즉시 점유·오류 표시와 관측 지점의 유효성 검사는 피코 로컬 규칙이 맡는다. jev는 상태 분류, chat은 관측된 통로·현재 이동 단계 안에서 다음 행동 하나와 이유를 제안한다. 경로 변경·음성 안내는 승인 뒤 실행한다. 민원 신고 비중으로 위험을 추정하지 않고 실제 보행 안전을 보장하지 않는다.
- **12시간 작업량(계획)**: 요구·계약 1h / 두 노드 단독 동작 3h / 이동 상태 전이·승인 연동 3h / 반복 측정·재차단·끊김·중복 입력 검증 2h / 발표 1h / 통합 지연 예비 2h. 구현 보장이 아니라 순수 제작 시간에 대한 계획이다.
- **3인 역할(계획)**: 하드웨어·기구·관측 보정 / 펌웨어·로컬 규칙·전원 / 상태 전이·Command Code·대시보드. 통합 검증은 공동으로 수행한다.
- **90초 핵심 장면**: (1) A가 막혀 B로 제안했는데 승인 전에 B까지 막힘→낡은 제안 폐기 (2) 통로 복구·이동 후 승차 요청→수락만으로 완료되지 않음→정차면 관측·담당자 확인, 통과 감지·당사자 확인 후 완료 (3) 노드 보고 끊김→해당 구간을 사용 가능으로 가정하지 않고 보류 표시.
- **리스크**: 보드 수·실제 관측 범위 미확인, API 키 만료. 우선 부품 수를 확인하고 Command Code 실호출을 복구한다. 통신 지연은 지연대로 표시하며 실시간 안전 동작을 클라우드 응답에 맡기지 않는다.

## 5. 구현 전 준비
- Command Code 키 재발급·재로그인 후 기존 승인 범위에서 최소 실호출 확인. 키 값은 출력하거나 파일에 저장하지 않는다.
- 보드·센서·서보·전원·USB 포트 수를 실제 키트로 확인한다. 1인당 키트 가격만으로 보드 2~3대가 있다고 단정하지 않는다.
- 버스도착정보는 활용신청·정류소 ID·실제 응답을 확인한 경우에만 실시간 기능으로 표기한다.
- 소음 안을 고르면 마이크 원시 파형과 C++ 배포 가능성을 먼저 확인한다. RP2040 지원 사실만으로 현장 TinyML 학습 성공을 전제하지 않는다.
- 기본 MicroPython 펌웨어와 필요한 라이브러리를 오프라인 보관한다.

## 6. GPT 최종 판정 반영
- `astra/round6.md`의 **조건부 채택**을 수용했다. 실내 사전 지정 경로·한 이동 건, 단일 상태 호스트, 현장 확인, 범위 밖 기능, 통합 예비 시간을 위 설계에 반영했다.
- 기존 세션의 시간 제한 이후 맥락을 압축한 새 GPT-6-Astra(max) 호출에서 최종 판정을 받았다. 새 점수·실제 성능·실물 검증의 합의는 아니다.
