# Pico Forge — 말로 만들고 실물로 검증하는 AI 메이커 (12라운드 최종, 2026-10-31 KST)

> 사용자 피드백: "너무 SDG 성격이 강해 보임. 최근 트렌드 조사해서 다시 확인."
> Claude와 GPT-6-Astra(max)가 각자 트렌드를 조사했다. 양측 모두 「분리배출 코치」를 교체하는 데 동의했다.
> 원문: `astra/round12_trend.md`(GPT 조사), `astra/round12_verdict.md`(최종 판정)

## 0. 결론
- **과제**: 사용자가 말로 기준을 말하면, LLM이 그것을 **피코가 실행할 수 있는 동작표**로 바꾼다. 사람이 승인하면 피코가 **실물로 시험**하고, 예상과 실제 측정의 차이를 근거로 수정한다.
- **쇼케이스**: 수동 투입형 **무게 선별 셀**(로드셀 + 서보 분기 + LED + 확인 버튼)
- **한 줄 피치**: "코드를 써 주는 AI를 넘어, 내가 말한 조건대로 현실에서 움직였는지 확인하는 AI."
- **SDG**: 4.4(디지털·기술 역량) 하나만. 선별 자동화의 산업 효과는 주장하지 않는다.

## 2. 왜 이 과제인가
- **피코가 필요한 이유**
  - 로드셀로 실제 무게를 재고 서보로 분기한다. 노트북 시뮬레이션으로는 드러나지 않는 영점, 흔들림, 경계값 문제가 실물에서 드러난다.
  - 서보 범위, 작동 시간 한계, 정지, 통신 단절 시 안전 정지는 네트워크와 무관하게 피코 규칙이 지킨다.
- **LLM이 필요한 이유**
  - 기준은 자유 문장으로 들어온다. 예: "무겁고 빨간 건 선물용, 애매하면 사람이 봐". 이런 문장의 조건, 예외, 모호한 말을 풀고 확인 질문을 한다.
  - **센서로 잴 수 없는 기준은 거절한다**(색·흠·당도).
  - 측정 기록이 의도와 어긋나면 수정안을 만든다. 예: 그릇 무게가 포함돼 잘못 분류됨 → 영점 조정 제안.
  - 고정 메뉴로는 미리 정하지 않은 기준을 처리할 수 없다.
- **'그냥 규칙 만들기 툴 아니냐'는 질문에 대한 답**(GPT 문안): "규칙 작성에서 끝나지 않고, 센서로 확인 가능한 조건만 실행하도록 제한하며, 예상 동작과 실제 측정의 차이를 근거로 수정·재시험하게 하는 도구입니다."

## 3. 파이프라인
```
자유 문장 기준 → LLM: 동작표 JSON {clarify, unsupported, tare_g, rules, default}
 → 코드: 스키마·장치 능력 검사(센서·출력 범위, 경계 겹침·빈틈) → 사람 승인
 → 피코: 동작표 실행(무게 측정 → 분기 서보·LED), 안전 한계는 로컬 규칙
 → 기록: 예상 분기 vs 실제 측정·분기 → LLM: 차이 원인 가설과 수정안 → 재승인 → 재시험
```

## 4. 실호출 시험 (2026-10-31, `deepseek-v4.1-flash`, 추론 low)
| 입력 | 결과 |
|---|---|
| "선물용은 무겁고 빨간 사과만 왼쪽, 흠 있는 건 주스용으로 오른쪽, 애매하면 사람이 보게 해줘" | 10.2초. 색·흠·용도 판단을 `unsupported`로 분리했다. '무겁다'의 g 기준, '애매'의 범위, 버튼 사용 여부, 영점을 되물었다. 규칙은 비우고 안전 기본값(가운데·노랑)을 뒀다 |
| "당도 12브릭스 이상인 것만 골라서 가운데로" | 4.7초. 당도는 측정 불가라고 거절했다. 대신 무게 기준을 원하는지 되물었다 |
| "200g 넘는 건 왼쪽, 나머지는 오른쪽. 그릇 50g은 빼고" | 경계값(200g 포함 여부)은 되물었지만 **출력이 잘려 JSON이 깨졌다(1/3)**. 대응: 출력 길이 제한·간결 지시·재시도·스키마 검사 |
- 시험한 것은 동작표 생성 단계뿐이다. 실물 실행과 수정 고리는 아직 시험하지 않았다.

## 5. 12시간 MVP
- **하드웨어**: 로드셀 + HX711(추가 약 1만 원[추정]), 서보 분기 1개(3방향), LED, 확인 버튼, 종이 경사로, 모형 과일(무게가 다른 물체)
- **소프트웨어**: 동작표 스키마와 검사기, 피코 동작표 실행기(최대 4규칙), 승인 화면, 실행 기록, 차이 분석과 수정 제안
- **12시간에서 뺄 것**(GPT 필수): 컨베이어 자동 이송, 무게 외 판정(색·흠·당도는 '측정 불가'로 표시). 임의 코드 생성·업로드도 하지 않는다. 동작표만 실행한다.
- **역할**
  - 하드웨어: 셀 기구, 로드셀 보정
  - 펌웨어: 동작표 실행기, 안전 규칙
  - LLM·서버: 스키마, 검사, 승인, 수정 고리
- **스타터 재사용**: USB 브리지, 대시보드 승인, `chat_text`(`reasoning_effort`)

## 6. 90초 시연
1. **심사위원이 즉석에서 기준을 말한다**: 예: "150g 넘으면 왼쪽, 애매하면 사람이 확인". LLM이 확인 질문을 하고 동작표를 보여 주면 승인한다.
2. **실물 시험**: 물체를 올리면 분기가 움직인다. 그릇 무게 때문에 하나가 틀리면 기록에 근거해 영점 조정 수정안이 나온다. 재승인 후 다시 시험하면 맞게 분류된다.
3. **거절과 안전**: "빨간 것만"이라고 하면 측정 불가라며 거절한다. 인터넷을 끊어도 이미 승인된 동작표와 안전 정지는 계속 동작한다.

## 7. 위험
- **'메뉴 고르기' 데모로 보일 위험**: 미리 등록하지 않은 복합 기준을 시연에서 즉석으로 처리해야 차별성이 생긴다.
- **출력 잘림·형식 오류**: 실호출 1/3에서 발생했다. 길이 제한, 재시도, 스키마 검사로 대응한다.
- **로드셀 안정화·보정**: 흔들림과 영점 문제가 실제로 생길 수 있다. 오히려 시연 소재가 된다.
- **교육 효과 미검증**: SDG 4.4 효과를 측정했다고 주장하지 않는다.

- 3위: AI 무대감독. 대본을 조명과 장치 큐로 바꾼다(SDG 4.4)
